# 市场全集与可执行报价必须使用两个时钟

## 30 秒心智模型

Structure 回答“当前有哪些市场、组合关系是什么”，Quote 回答“这一刻这些市场多少钱”。
前者变化慢，后者变化快，所以同一个 Structure 必须允许连续产生 Q0、Q1、Q2：

```text
Structure S0 ─┬─ Quote Q0 ─ Opportunity O0
              ├─ Quote Q1 ─ Opportunity O1
              └─ Quote Q2 ─ Opportunity O2
```

两个产品共享 lineage，但不能共享 generation identity。否则恢复器会把
`quote:<structure-digest>` 当作唯一代次，重复报价既无法表达，也无法独立恢复。

## 为什么 Q0 曾经掩盖缺陷

初始实现令 Quote digest 恰好等于 Structure receipt digest。旧恢复查询因此在 Q0 看起来正确：

```text
structure:abc...  -> quote:abc...
```

引入 recurring Quote 后，真实关系变为：

```text
structure:abc...  -> quote:def...
```

正常终态写入知道 `def`，但旧 lost-wakeup sweep 又从 Structure 列推导出 `abc`。只要最后一个
producer 遇到一次 `FOR UPDATE SKIP LOCKED`，Q1 certifier 就永久停在 `waiting`。修复不是增加
timeout，而是让恢复查询使用与写入侧相同的 Quote identity。

## 为什么恢复出的过期 Q1 仍应被隔离

生产恢复时，Q1 的 140 个 batch 全部真实成功，但价格已经超过 900 秒。Quote pointer 可以发布
它来恢复代次序列；Opportunity 不能把旧价格包装成当前套利机会，所以会终态隔离 O1，并由 cadence
立即接纳 Q2。这里的正确预案是“告警、跳过过期机会、继续下一代”，不是重启 24 小时整窗，也不是
放宽 freshness SLA。

## 设计取舍

- Structure identity 表示市场全集真相；Quote identity 表示一次价格采样运行。
- lineage 用外键关系表达共享父代，不用 digest 相等来偷懒。
- direct wake 是低延迟路径；durable sweep 是丢失唤醒恢复路径，两者必须使用相同代次键。
- freshness 是下游产品门，不应反向伪造上游任务失败。
