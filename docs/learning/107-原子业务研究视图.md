# 原子业务研究视图

## 30 秒心智模型

M1 的业务界面不是把几个 HTTP 接口“拼起来”。它读取一次 `BusinessOverviewV1`：同一份数据库快照同时给出 Structure、Quote、Analysis 与 Opportunity 的发布状态和世代关系。因此“当前 0 个认证机会”只有在该快照的 opportunities 为 `available` 且 `count=0` 时才成立。

## 代码地图

- `src/polyarb/control_plane/postgres.py:8809`：在只读 `REPEATABLE READ` 事务中构造业务快照。
- `src/polyarb/control_plane/api.py`：将该快照原样暴露为 `/perception/business-overview`，失败只返回 unavailable。
- `src/polyarb/cli_control_plane.py`：日报 brief 只读取该接口。
- `dashboard/app/business/`：总览以及 Structure、Quotes、Analysis、Opportunities 四个研究页。
- `src/polyarb/control_plane/postgres.py:4800`：Structure 范围回执和其研究索引 rows 同一事务提交。
- `src/polyarb/control_plane/postgres.py:4482`：Quote 批次回执和其研究索引 rows 同一事务提交。
- `dashboard/lib/business-research.ts`：严格校验代次绑定的分页明细，不接受任意 JSON 伪装成业务数据。

## 为什么先看 Structure 和 Quote

最终机会通常很少；它不是 M1 全部工作量。先在 Structure 页确认市场结构 generation 与组件覆盖，再在 Quotes 页确认报价 generation 的 Structure parent。若 Quote 是 `lagging`，即便留下历史机会，也不能说它是当前业务结果。

Analysis 页目前显示 `not-published` 并不是“没有分析过”。当前投影只持久化了认证成功的 rows，无法从它反推 no-edge 或 rejected 的数量。把未知显示成未知，比用最终零机会补造一条漏斗更可靠。

## 明细页为什么有时显示“索引未物化”

Structure 和 Quote 的明细索引是随新的范围/批次回执写入的，但只有对应
generation 被认证并成为 `*:current` 后才允许读取。这样页面不会把进行中的
范围、旧 generation 或 R2 的临时内容混进业务结论。

刚引入该索引时，已经发布的历史 generation 没有追溯写入；页面会明确显示
`research-index-not-materialized`，不是“0 行”。等待下一次完整 generation
认证或执行受控回填后，才能研究该 generation 的高密度明细。

## 自检题

1. `opportunities.count=0` 但 status 是 `not-published`，能否写“今天没有机会”？
2. 为什么 Quote 页要展示 parent Structure generation？
3. Analysis 为何不能仅用 `opportunities.count` 计算 rejection rate？

答案分别是：不能；用来检验输入世代一致；因为未认证的候选、不可执行组和无边际组并没有被当前投影保存。
