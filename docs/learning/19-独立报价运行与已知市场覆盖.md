# 独立报价运行与已知市场覆盖

## 30 秒心智模型

一个 snapshot 告诉我们“这一刻已知哪些 neg-risk 腿”；一个 quote run 才告诉我们
“这一批腿在同一次只读 CLOB 收集里各自看到什么 ask”。扫描器只接受**完整完成的同一
run**，并同时检查 quote 与 universe 两个年龄。这样宁可返回 unavailable/stale，也不会把
缺腿、旧报价或混批报价误写成 `count=0` 或可成交套利。

```text
latest membership snapshot
          │（known universe）
          ▼
read-only CLOB collection ──► collecting ──► complete / failed
                                           │
                                           ▼
                            quote age + universe age pass
                                           │
                                           ▼
                         gross-before-fees opportunity candidates
```

这是一条本地数据路径：它会写本地 SQLite，但不会部署、调度或下单。它的实现正确性不等于
生产 cadence、容量或 readiness 已被证明。

## 为什么“整组原子完成”重要

neg-risk buy-all 的 claim 依赖同组每一腿。假设两腿 ask 是 `0.46 + 0.49 = 0.95`，最小
ask size 是 `8`，则毛 edge 是 `500 bps`，理论毛利润是 `8 × (1 - 0.95) = 0.40`。如果第二腿
的 `0.49` 来自上一次 run，而第一腿来自本次 run，这个 `500 bps` 不是同一时点可执行的事实。
因此 collector 要么完整记录本次 universe 的 terminal rows 后 complete，要么失败；scanner
只接受 complete run。这个例子仍未扣 fee、滑点、成交失败或 oracle 风险，绝不是订单指令。

## 实际操作边界

```bash
# 有最新本地 snapshot 时：远端只读，写本地 SQLite
make collect-neg-risk-quotes db=data/state.db

# 只看同一 complete run；任一时钟超限都非零退出
make scan-arb-quotes db=data/state.db min_edge_bps=0 \
  max_quote_age_s=300 max_universe_age_s=50400

# 只验证本地实现合同；没有网络、deploy 或 scheduler 行为
make eval-local profile=opportunity-feed-cadence-sla
```

known universe 有一个刻意的盲点：新上市的组不在当前 membership snapshot 内，就不会进入这次
collection；要等下一次 snapshot 后才可能被包含。这个取舍优先保证“这一批腿可归属”，而不是
假装覆盖了实时全市场。

## 设计取舍

- **完整性优先于频率**：不混合 run 会放弃部分可见报价，却避免虚假的可执行 edge。
- **双时钟优先于有行即成功**：quote 新鲜不足以说明 universe 仍有效；universe 新鲜也不能覆盖
  陈旧 quote。
- **本地入口优先于生产自动化**：当前没有 cron/deploy，故没有生产 capacity 观察、重复完整 run
  或不可变证据。以后是否 rollout 必须先单独获得部署/调度授权，再做时间戳化只读容量观察。

## FAQ 增量

### HTTP 503 能不能当成没有机会？

不能。它表示 quote run、quote 年龄或 universe 年龄未达到 HTTP 合同；没有可用数据时，系统
必须拒绝结论，而不是输出一个看似正常的零。

### 现在可以把它接成生产 cron 吗？

不可以。本次只交付了本地命令与离线合同。生产部署/调度和时间戳化只读容量观察是尚未授权的
后续 gate；还要有重复 complete run 与不可变证据，H-009 才能重新评估。
