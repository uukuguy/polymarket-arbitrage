# 认证当前机会读模型

## 30 秒心智模型

Dashboard 不能从“最新 Group + 最新 Quote + 最新 fact”各自取一行再现场拼机会，因为三行可能属于不同版本。生产写事务会同时生成一条绑定 `group revision + membership + fact + quote batch` 的 current-authority 行，并把它的 hash 汇入 O(1) aggregate。HTTP 只分页读取这份认证投影；任一绑定、hash、journal 或 aggregate 不一致都返回 unavailable，而不是零机会。

- `dashboard/app/perception/page.tsx:129`：只渲染服务端证据，Structure/Quote age 使用同一 status server clock。

## 为什么状态计数是全局，Structure 状态不是

`watching / no-edge / unavailable` 每次 Candidate 终态写入时原子增减 aggregate，所以读取成本固定。`stale / invalidated` 属于完整 Structure universe；当前公开接口只返回一个 bounded page，因此 Dashboard 必须标注 “returned bounded page”，不能伪装成全局计数。

## v2→v3 为什么不是 ADD COLUMN

owner manifest 认证的是 canonical SQLite DDL 和 trigger SQL。`ALTER TABLE ADD COLUMN` 可能留下与 fresh v3 不同的 schema 指纹，同名 `CREATE TRIGGER IF NOT EXISTS` 也不会替换旧 trigger。迁移因此在一个 `BEGIN IMMEDIATE` 内：

1. 先认证 exact v2 manifest、journal/root 和 Candidate replay；
2. 从 retained raw/checkpoint seed 精确回填 current rows；
3. 让旧 trigger 记录并消费回填 mutation；
4. canonical 重建 aggregate 与 trigger；
5. 最后切换 v3 guard/root并复验。

实现入口见 `src/polyarb/perception/store.py:1851`。任一 deadline、损坏或并发竞争只会留下完整 v2 或完整 v3。

## 设计取舍

- 当前机会使用 keyset cursor，不使用 offset；延迟与历史总量无关。
- JSON 数字只用于展示；资金 authority 仍不在这个 observer-only read model。
- historical opportunity transition 尚未在本任务暴露；“当前”不能冒充“历史”。
- unavailable 是证据失效，语义上永远不等于 count=0。
