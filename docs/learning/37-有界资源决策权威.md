# 有界资源决策权威

## 30 秒心智模型

资源控制器每次先采一份 hot-path sample，再用同一套确定性 policy 生成 decision。
sample 和 decision 不是两张“最新状态表”，而是一条必须从历史 floor 重放的证据链。

checkpoint 保存已压缩 prefix 的最后 decision 和 digest；suffix 保留最近最多 512
对 sample/decision。达到 513 对时，writer 在同一事务中把最旧 257 对压入
checkpoint，只留下 256 对。reader 从 checkpoint anchor 开始重放 suffix，最后
结果必须等于 checkpoint 认证的 tail digest。

所以“数据库里只剩 256 对”不代表历史丢了；它表示 257 对历史已由 checkpoint
承诺。任何 checkpoint、suffix、尾部删除或 policy replay 不一致都返回
unavailable，而不是沿用一个看起来合理的旧 mode。

## 为什么 checkpoint 每次 decision 都更新

只在 compaction 时写 checkpoint，能证明 prefix，却不能发现 retained suffix
最后一行被删除。当前实现让 `last_decision_digest` 绑定从 prefix 到当前 tail 的
完整 pair chain，并在每次成功 writer 中 owner-journaled 更新：

```text
pair_digest = H(previous_digest, sample row, decision row)
checkpoint_hash = H(floor identity, prefix digest, current tail digest)
```

因此删除最后 decision/sample 后，剩余行仍能通过单行 JSON 校验，但重算出的 tail
digest 不再等于 checkpoint，reader 会 fail closed。

## 原子写入与失败证据

正常写入在一个 `BEGIN IMMEDIATE` 中完成：

1. 验证 owner manifest、checkpoint、suffix 和现有 breadcrumb；
2. 追加 sample；
3. 按 deterministic policy 追加 decision；
4. 更新 owner-journaled checkpoint；
5. 必要时删除已压缩的旧 pair；
6. commit。

任一步失败都会回滚 sample、decision、checkpoint 和压缩删除。authority
校验/硬上限失败后，writer 再用独立事务写
`neg_risk_evidence_failures(component='resource')`。下一次成功 writer 先独立写
`recovered_at_ms`，再开始新的业务事务。

## Dashboard 该怎样读

Resource 面板同时显示：

- current mode / reason；
- policy age 和 TTL remaining；
- Candidate quote p95、missing quote、worker 状态等输入；
- bounded recent mode transitions；
- `next_before_sequence` 和 compaction history floor。

`candidate_quote_p95_ms=null` 是“没有观测值”，不是 0 ms。整个 resources envelope
校验失败时，overview unavailable；页面不会单独拿旧 mode 继续显示绿色。

## 设计取舍

- high/low water 是 512/256，public validation 的损坏硬上限是 1,024。
- resource policy 逻辑未改变；变化只在 evidence retention 和 read authority。
- `perception:resource_evidence` 没有 feature flag。即使 controller disabled，已经
  存在的损坏证据仍必须让 strict `/health` 返回 503。
- API 是 observer-only；它不会触发 sample、decision、producer 或交易。
