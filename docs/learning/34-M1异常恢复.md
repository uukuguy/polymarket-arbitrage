# M1 异常恢复：失败不可怕，无法证明恢复才可怕

## 30 秒心智模型

M1 不把“进程重新启动了”当作恢复。每个异常必须经过持久化状态机：

```text
detected → classified → contained → recovering → verified
                                         └──────→ escalated
```

`verified` 的门票不是日志或经过了多少秒，而是恢复开始以后由真实生产者写入的事实：Candidate 在一个事务中写入的成功收据、完整同组 Quote batch 与 terminal fact，Discovery 推进的 cursor batch、Reconciliation 推进的 checkpoint，或绑定当前 release 的响应式 HTTP 探针。

## 代码地图

- `src/polyarb/perception/incidents.py`：append-only 生命周期与恢复证据核验。
- `src/polyarb/perception/resource_controller.py`：热路径优先的 deterministic shedding、cooldown。
- `src/polyarb/perception/supervisor.py`：无 shell 子进程、输出限长、超时 terminate→kill、有限退避。
- `src/polyarb/perception/worker_cli.py`：一个进程只运行一个 producer。
- `src/polyarb/http/health.py`：从持久化事实生成 `perception:open_incidents` 与 `perception:resource_mode`。

## 为什么 incident 只追加、不覆盖

覆盖一行只能告诉你“现在是什么”，不能回答“何时检测、采取了什么动作、恢复证据是哪一笔”。append-only event 让并发 transition 在 `BEGIN IMMEDIATE` 下按 durable latest state 做 CAS；非法跳级和 terminal `verified` 重开都会失败。相同 scope/kind 的未关闭异常重复检测时返回原 incident，不制造告警风暴。

## Resource shedding 的顺序

Quote p95 变热、缺 Quote 或 Candidate worker 异常时：

1. 关闭 Reconciliation；
2. 缩小 Discovery batch 与 duty；
3. 放慢 normal Candidate，但不放慢 high Candidate；
4. 始终保留 HTTP。

Candidate 集为空时扩大 Discovery，但 `health_claimed=false`：扩大探索不是“系统健康”的替代证明。恢复到 normal 还要经过 cooldown，避免阈值附近来回抖动。

## 子进程边界

生产 child command 是固定 argv tuple，使用 `create_subprocess_exec`，不经过 shell。stdout/stderr 会被持续 drain，但仅保留限长 tail，并对带项目前缀或后缀的 secret/token/key 形式脱敏。

supervisor 在 spawn 前原子预留 attempt；若主进程在 spawn/receipt 之间崩溃，下次启动先把遗留 reservation 收敛成 `spawn-error`，再分配新 attempt，避免“数据库没记录、进程却跑过”的幽灵执行。child 在启动后自行生成 heartbeat authority 原像，SQLite 只保存域分离 hash；stall deadline 只接受能证明该原像、且绑定当前 run/attempt 的 heartbeat。健康检查会回放完整历史链，因此篡改一条旧 heartbeat 也会 fail closed。

Candidate 的恢复证明还多一层原子边界：`publish_candidate_success()` 在同一事务写 Quote batch、terminal fact 和带精确 row ID/hash 的 success receipt。先 `publish_quote_batch()`、再 `record_candidate_watch_fact()` 即使字段完全相同，也不会生成这张收据，不能把 incident 关闭。

## 操作入口

```bash
make run-perception-worker component=candidate
make run-perception-worker component=discovery
make run-perception-worker component=reconciliation
```

这些入口仍受 `.env` 中双层 default-off flag 约束。正常生产由 supervisor 启动，不建议手工长期运行。

## FAQ 增量

### 为什么数据库里只存 heartbeat hash？

如果 supervisor/数据库同时拿到可直接签 heartbeat 的 secret，父进程就能在 child 卡死时伪造“仍在推进”。现在原像只存在于 child 进程内存，数据库只存 hash；父进程只能验证，不能代写有效 heartbeat。

### 为什么 disabled producer 不显示成 unhealthy？

严格健康只检查配置中实际启用的 producer。未启用组件既不消费 resource decision，也不生成 liveness 义务；否则默认关闭的功能会永久制造假故障。
