# 健康投影总预算：每条 SQL 很短，总和仍会超时

## 30 秒心智模型

`/healthz` 为了给操作者完整事实，会读取容量、incident、Structure、Quote 等多个权威视图。
每个 SQLite 读取都有 250ms 的忙等待上限，但它们是串行的：写压下的总预算不是 250ms，
而是多个 250ms 加上正常查询时间。四秒超时会让健康线程在后台完成剩余读取，并占住唯一 lane，
下一次巡检就只看到“饱和”。

八秒不是放弃失败检测：Fly service check 与 Polywatch 的总 deadline 是十秒，仍保留两秒
用于 JSON/网络，并且真正无法完成时依旧返回可告警的 P1 envelope。

## 代码地图

- `src/polyarb/http/health.py:_HEALTH_READ_TIMEOUT_S` — health 的内部完整投影预算。
- `src/polyarb/http/opportunity_read_health.py:BoundedReadLane` — 防止无限堆积的唯一 worker。
- `fly.toml:http_service.checks.timeout` 与 `scripts/polywatch/healthz_watcher.py` — 十秒外部边界。
