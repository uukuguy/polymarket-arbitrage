# 77 — 长认证租约心跳

## 30 秒心智模型

lease 不是“拿到一次就永远有效”的锁，而是带截止时间的所有权证明。Structure certification
需要逐段重读大量 R2 artifact 做内容 parity；只要总时长可能超过 30 秒，就必须在仍是同一
owner/epoch 的前提下续租。续租失败意味着已经失去写入权，必须停止，不能继续发布 manifest。

## 代码地图

- `src/polyarb/control_plane/structure_worker.py:255`：心跳周期是 lease 的三分之一。
- `src/polyarb/control_plane/structure_worker.py:270`：仅到期时以当前 lease 调用 fenced
  `heartbeat`，并替换 `active_lease`。
- `src/polyarb/control_plane/structure_worker.py:334`：每个 R2 parity 段之前触发检查；v3
  shard 路径也在同一回调下。
- `src/polyarb/control_plane/structure_worker.py:291`：最终 certify 使用续租后的
  `active_lease`，不是最初那张已过期的 lease。

## 关键代码

```python
# structure_worker.py:270-280
def heartbeat_if_due() -> None:
    nonlocal active_lease, last_heartbeat
    if current_monotonic - last_heartbeat < self._heartbeat_interval_seconds:
        return
    active_lease = self._control_plane.heartbeat(
        active_lease, now=self._now(), lease_seconds=self._lease_seconds
    )
```

这是“续同一把锁”，不是重新 claim job。数据库用 owner + epoch 围栏；若另一台机器已在旧
lease 到期后接管，`heartbeat` 会抛出 `StaleLeaseError`，而不会把新 owner 的工作覆盖掉。

## 设计取舍

心跳不是把 30 秒 lease 改成长 lease。短 lease 保留了故障接管的速度；每三分之一续一次
只在长任务真实存活时延长所有权。它同时要求最终提交使用最新 lease，避免“后台已失权却仍
然发布”的伪安全。
