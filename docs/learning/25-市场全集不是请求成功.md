# 市场全集不是请求成功

## 30 秒心智模型

一次 HTTP 200 只能证明“这次响应到了”，不能证明“市场已经全部取完”。旧链路在
offset 2,100 遇到 HTTP 422 后，把已取得的子集当作全集；随后每一层都对这个子集
保持原子一致，最终仍能稳定地产生错误机会。

现在 M1 要连续拿到三张通行证才允许 M2 继续评估：

```text
markets/events keyset 到终止 cursor
              │
              ▼
event exact membership + standard/augmented 分类
              │
              ▼
complete published snapshot
              │
              ▼
同一 verified universe 的完整 quote run
              │
              ▼
verified-standard-neg-risk（只供 M2 评估，不是下单许可）
```

任一通行证缺失都 fail-closed。旧的完整版本可以帮助定位，但不能替最新失败尝试开
绿灯。

## 2,100 行事故是怎样发生的

旧客户端使用 offset 分页。生产式请求在 offset 2,100 收到 HTTP 422，客户端把这个
4xx 当作“没有下一页”，所以：

1. SQLite 中确实有很多市场；
2. quote worker 也确实为本地每条腿拿到了报价；
3. run 的 1,278/1,278 也确实成立；
4. 但没人证明第 2,101 行之后是否还有属于同一事件的市场。

Michigan Republican Senate Primary（event `111080`）在本地子集中只剩 Kent
Benham 与 Fred Heurtebise 两条腿，权威 event 结构实际有 33 个成员，且
`negRiskAugmented=true`。把两腿 ask 相加不是“买齐全部结果”，所以 99% 级 gross
edge 是数据结构错误，不是套利。

keyset 修复的关键不只是换 URL，而是保存 completion proof：只有服务端明确不给出
下一 cursor 才算完成。重复 cursor、响应形状错误、请求失败和页数上限都让本次尝试
成为 `incomplete-source`，不得发布成市场事实。

## Exact membership 为什么必须来自 event

相同 `negRiskMarketID` 只能说明市场声称属于同一组，不能证明本地已经看到组内所有
成员。event 对象才提供结构集合，包括当前不能交易的 placeholder 与 Other。

M1 对每个成员保存：

- `event_id`、`group_id`、`market_id`；
- `member_kind = named | other | inactive-reserved`；
- `active`、`closed`；
- 由排序后完整成员生成的 `membership_hash`。

quote universe 会再次要求 market 行集合、membership 行集合、expected count、
active named count 和 hash 全部一致。这样缺一腿、混入别的 event、重复 ID 或状态
漂移都不会被解释成正 edge。

## Standard 与 augmented 不是一个策略

当前 `neg-risk-buy-all` 只支持 standard neg-risk：完整 named outcome 集合已知，
每条必需腿可交易，买齐所有 YES 才能讨论 `sum_asks < 1`。

augmented neg-risk 允许稍后明确的新结果，并由 Other 承接未命名获胜者。买当前 UI
可见的 active named outcomes 并不覆盖所有结算路径。因此 M1 会：

- 保留完整 augmented 结构事实；
- 标记 `complete-unsupported`；
- 以 `augmented-neg-risk-not-supported` 计入 rejection；
- 永不把它放进 standard buy-all opportunity。

这不是“漏掉一个机会”，而是拒绝用错误 payoff 模型交易。

## 两个健康时钟

`market_truth:coverage` 看最新 snapshot 尝试。只要最新尝试缺页、membership
不完整或未发布，它就是 fail。

`market_truth:last_complete_age_seconds` 看最近一次 complete、published truth 有
多旧。它回答“最后一个可用锚点是什么时候”，不回答“最新尝试是否成功”。

例子：12:00 完整发布，12:10 新尝试在 events cursor 失败。12:10 的正确状态是：

- coverage：fail / incomplete-source；
- last complete age：约 10 分钟；
- overall strict health：fail；
- Polywatch：`L1 market truth coverage failed`，进入既有去重/恢复迟滞；
- M2：停止消费，不得回退到 12:00 冒充当前全集。

## Provenance 如何防止混批

生产 opportunity 的顶层与每条候选必须能回答：

- `source_snapshot_id`：结构事实来自哪次完整发布；
- `event_id` + `membership_hash`：是哪套 exact members；
- `universe_hash`：本轮所有可报价腿的身份摘要；
- `quote_run_id`：所有 ask 是否来自同一完整 run。

诊断入口 `make diagnose-arb-feed-prod min_edge_bps=0` 会验证这些字段和
`coverage=verified-standard-neg-risk`。合法 `available-zero` 表示扫描了完整
verified universe 后没有正 edge；503 或 invalid response 只表示不知道。

## 实战操作

```bash
make smoke-health-prod
make smoke-market-truth-prod
make diagnose-arb-feed-prod min_edge_bps=0
make polywatch-healthz-dry
```

检查顺序：

1. release ID 是否是预期发布；
2. market truth coverage 是否 complete/pass；
3. last complete age 是否在阈值内；
4. opportunity coverage 是否是 verified-standard-neg-risk；
5. rejections 是否保留 augmented 原因；
6. 每条候选的五类 provenance 是否完整。

只有这六项同时成立，M1 才能把候选交给 M2 做费用、滑点、容量和执行风险评估。

## 设计取舍

- **全 snapshot fail-closed**：一个 source 不完整就拒绝发布；代价是短暂不可用，
  收益是不会把未知缺口伪装成零机会。
- **结构事实包含不可交易成员**：多存一些行；换来对 payoff 空间的完整描述。
- **augmented 明确拒绝**：当前少做一类策略；换来 standard buy-all 的语义可证明。
- **两个健康时钟**：监控字段更多；换来“最新失败”和“上次成功有多旧”不再混淆。
- **provenance 写入响应**：payload 略大；换来人工和 M2 都能复核同一份数据身份。

## FAQ 增量

### Q：旧完整快照还没过期，为什么不能继续给 M2？

因为最新失败说明市场结构可能已经发生变化，而我们不知道变化落在缺失页还是已知页。
旧版本可用于排障和比较，不能冒充当前全集。恢复条件是后续一次新尝试重新完成
keyset、membership、publication 与 quote-run 全链路。
