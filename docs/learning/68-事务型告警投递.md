# 事务型告警投递

## 30 秒心智模型

采集 worker 的职责到 outbox 为止；它不能因为 Telegram 或网络波动而占住市场采集
lease。独立 alert worker 领取一条 durable outbox intent，投递后在同一事务内更新
outbox 状态并追加 delivery receipt。worker 在投递期间消失时，lease 到期后另一个
worker 接管，原意图不会丢失。

```text
incident event + outbox intent → alert lease → channel attempt → immutable receipt
```

## 代码地图

- `alembic/versions/013_m1_alert_delivery_leases.py`：给既有 outbox 增加 fenced
  `lease_owner / lease_epoch / lease_expires_at`，不重建也不清空历史。
- `src/polyarb/control_plane/postgres.py:claim_alert_delivery`：`SKIP LOCKED`
  领取一条 due/过期 outbox。
- `src/polyarb/control_plane/postgres.py:finish_alert_delivery`：fenced 状态改变和
  `m1_alert_deliveries` append-only receipt。
- `src/polyarb/control_plane/alert_delivery.py`：独立 worker；本阶段的 dashboard
  channel 以 durable operator visibility 为成功回执。
- `src/polyarb/control_plane/scheduler.py`：第九个 bounded turn，永远不与
  Structure/Quote 共享内存锁。

## 当前边界

`dashboard` 的 receipt 是“控制面可读取”的证据，不是假装用户手机已收到。外部
Telegram/webhook sender 必须在具名环境配置、独立验收后接入这个 sender 边界；未配置
的 channel 记录 retryable receipt，而不会丢弃 intent 或影响数据采集。
