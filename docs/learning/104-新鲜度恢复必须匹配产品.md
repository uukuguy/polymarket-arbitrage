# 新鲜度恢复必须匹配产品

## 30 秒心智模型

滚动资格只有一个当前暂停原因，但新鲜度事实来自三个独立产品。若
`freshness.structure` 暂停后由 `freshness.quote` 或一次无关的
`recovery.confirmed` 解锁，系统就会把“别处恢复了”误当成“Structure 已恢复”。

正确状态转换必须同时满足三个条件：

```text
当前原因 = freshness.<product>
新事实产品 = 同一个 <product>
新事实年龄 <= 该事实声明的 SLO
```

满足后只解除暂停，不补算暂停期间的墙钟时间；下一段健康间隔才继续增加有效秒。

## 为什么不能只看 `reason="healthy"`

`healthy` 只说明这条事实本身没有触发阻断，不说明它观测的是哪个数据产品，也不说明它
修复了当前暂停根因。恢复是一个带因果对象的转换，不是“看到任意好消息就清零红灯”。

## 为什么恢复瞬间不增加覆盖时间

从 stale fact 到 fresh fact 之间，系统无法证明 Structure 一直有效。把这个墙钟间隔直接加入
coverage 会制造 24 小时证据。恢复事实只是新的时间锚点；之后连续健康的时间才是可计入证据。

## 与生产 cadence 的边界

状态机能正确暂停和恢复，不代表生产端一定能在 900 秒内持续生成新 Structure。若完整源窗口
天然慢于 SLO，必须重新审计数据产品身份和刷新拓扑；不能靠本修复或随意调大 SLO 掩盖。
