## Decisions Made

1. **Dead-code activation strategy** — Plan 02 PLAN.md framed the mirror sub-check as "TODO/placeholder", but inspecting `_build_l2_health_checks` showed Phase 03 Plan 06 had already wired the live getter call. The only missing piece was the **Settings field** (`l2_mirror_enabled`) that gated the entire block. So Task 2 became thresholds-overridable refactor + l2_main constructor kwarg, not a sub-check rewrite. Documented in commit `b89482a`.
2. **Status-mapping boundary semantics** — Plan said "age >= fail → fail; warn <= age < fail → warn; age < warn → pass". Original hardcoded code used `<` comparisons (age < _MIRROR_PASS_S → pass; age < _MIRROR_WARN_S → warn; else fail). I switched to `>=` comparisons in the order specified to make the boundary deterministic and match the IETF-style threshold semantics.
3. **`_derive_notes_from_issues` filters to API_UNREACHABLE only** — Plan said "any L1 layer-1/layer-4 API_UNREACHABLE issue". I implemented that exactly (filter by `Category.API_UNREACHABLE`, ignore layer). Excludes ZOMBIE_MARKET / GHOST_BOOK / UNKNOWN — confirmed in test 4.
4. **Truncation strategy** — `detail[:80]` per issue, `joined[:200]` overall (semicolon-joined). Plan said "truncate from rightmost if needed". My implementation truncates from rightmost via slicing; verified with 300-char issue inputs.

**3. [Rule 1 — Behavior alignment] /health status boundary semantics**
- **Found during:** Task 1 GREEN
- **Issue:** Existing hardcoded code used `if age < PASS_S: pass; elif age < WARN_S: warn; else: fail` — i.e. age=300 → warn, age=1800 → fail. The plan asked for "warn <= age < fail → warn; age >= fail → fail" which is a different semantic (the threshold value IS the boundary, not the open lower bound).
- **Fix:** Updated to `if age >= fail_s: fail; elif age >= warn_s: warn; else: pass`. Boundary-value tests (age == warn_s) now deterministically warn rather than possibly pass.
- **Verification:** Test 7b (450s vs warn=300/fail=600) returns warn.
- **Committed in:** `b89482a`

**4. [Rule 2 — Critical missing field] Added `output` field to mirror sub-check**
- **Found during:** Task 1 GREEN
- **Issue:** Existing mirror sub-check returned `status` + `observedValue` only, no operator-readable explanation. When `/health` returns fail with `observedValue=700` it's not immediately obvious what unit / what threshold was crossed.
- **Fix:** Added `output: "last mirror push 700s ago (warn>=300s, fail>=600s)"` (or `"cold-start: never mirrored"` for None case). Matches the schema already used by the WS sub-checks (which had `output: "ws_consumer not yet wired ..."`).
- **Verification:** Test inspection.
