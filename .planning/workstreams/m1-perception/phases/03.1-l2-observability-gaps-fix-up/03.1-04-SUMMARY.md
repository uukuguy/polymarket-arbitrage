## What Landed

### Task 1 — `_is_dns_jitter` + tenacity wrap on Gamma /markets

- New helper `polyarb.snapshot.orchestrator._is_dns_jitter(exc) -> bool`. Returns True ONLY for `httpx.ConnectError` whose `str(exc)` matches `[Errno -5]`, `[Errno -3]`, `EAI_NODATA`, `EAI_AGAIN`, `Name or service not known`, or `Temporary failure in name resolution`. All other shapes (`Connection refused`, `TimeoutError`, raw `OSError`) return False.
- Phase-2 streaming block in `run_snapshot()` now wrapped in `tenacity.AsyncRetrying` with:
  - `retry=retry_if_exception(lambda e: _is_dns_jitter(e) and not first_frame_seen)`
  - `stop=stop_after_attempt(3)` — max 3 attempts total
  - `wait=wait_exponential(multiplier=1, min=1, max=5)`
  - `reraise=True` — after exhaustion the existing `except Exception` clause fires unchanged, appending the API_UNREACHABLE issue (chain-truth preserved)
- `first_frame_seen` sentinel ensures middle-of-stream errors are NOT retried — a partial stream that consumed N markets is not an idempotent retry boundary.

### Task 2 — `FAILURE_THRESHOLD` 3 → 5

- `src/polyarb/daemon/scheduler.py:51` changed from `3` to `5`; module docstring + class docstring updated to reflect the new state machine name (5-failure-pause).
- `src/polyarb/daemon/alerts.py` docstring updated (3-failure → 5-failure dedup mention). `src/polyarb/http/control.py` historical Bug #8 reference (`3 consecutive snapshot failures`) intentionally left unchanged — it documents the Phase 02.1 fix at the time, and rewriting it would muddy provenance.
- 4 tests refactored to drive loops off `SnapshotScheduler.FAILURE_THRESHOLD` (scheduler.py:51 class attribute) rather than hardcoded `3` — assertions now invariant under future threshold tuning.
- New `test_pause_after_5_failures_not_3` pins to literal 5 explicitly: 4 failures stay RUNNING, the 5th transitions to PAUSED. Purpose: catch silent regressions back to 3 (or any other value).

### Task 3 — `scripts/dns_baseline_probe.py` + Makefile target

- Pure-stdlib script — no project imports. Resolves 3 Polymarket hostnames (gamma-api, clob, data-api) N times with configurable interval; emits one JSON-line per probe + one summary JSON-line; exit 0 on all-pass, 1 on any-fail.
- Tunable via `POLYARB_DNS_PROBE_N` / `POLYARB_DNS_PROBE_INTERVAL_S` env vars.
- Default cadence: 30 probes × 3 hosts × 2s interval = ~3 min local runtime.
- Makefile target `dns-baseline-probe` added in a new clearly-separated `Phase 03.1 — DNS observability (Plan 04)` section at EOF, so Plan 06's append lands cleanly below it without merge conflict.
- Local smoke verified: `POLYARB_DNS_PROBE_N=3 INTERVAL=0.5` → 9/9 OK, summary printed, exit 0.
