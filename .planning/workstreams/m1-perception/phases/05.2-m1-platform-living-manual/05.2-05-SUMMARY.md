# Phase 05.2 Plan 05: Verified Living-Manual Closure

workflow, proportional verification, a timestamped read-only production

## Delivered Contract

- `make smoke-l2-health-prod` remains the always-200 `/healthz` reachability
  probe and is explicitly not a business-health conclusion.
- `make smoke-l2-health-strict-prod` invokes
  `curl --disable --request GET` for the production L2 strict `/health`, so a
  user curlrc cannot change the method or client behavior. It prints the HTTP
  status and response body and has an explicit `else ... exit 1` branch unless
  HTTP status is 200. A focused word-boundary scan of this target's recipe
  excludes flyctl, scale, deploy, POST, restart, secret/secrets, schema,
  migrate/migration, and chaos operations.
- The manual's capability matrix, five-minute daily flow, production read-only
  flow, candidate-chain flow, safety index, and auditable sync log all point to
  the Make entry instead of asking operators to execute a direct URL workflow.

## Manual Product and Operations Role

[`docs/M1-市场感知平台使用手册.md`](../../../../../docs/M1-市场感知平台使用手册.md)
is the stable M1 product-description and daily-operations entry point. It
separates `已验证可用`, `有条件可用`, and `尚不可用` capabilities,
routes volatile production truth to `.planning/CURRENT.md` and strict health,
and explicitly states that M1 evidence does not authorize real-money orders.

The maintenance protocol requires any M1 Make/CLI/health/Dashboard/schema or
readiness-contract change to update the manual in the same change, run
`make docs-m1-check`, and satisfy the scoped staged pre-commit guard. Readiness
changes must update CURRENT evidence before changing the stable manual.
