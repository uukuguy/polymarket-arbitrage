# Phase 05.2 Plan 02: M1 Product and Operations Living Manual

Created the stable Chinese operator entry point for the M1 market-perception
platform and exposed its offline repository contract through
`make docs-m1-check`.

## Delivered Manual Contract

The manual has the approved ten-section structure:

1. 30-second product mental model and real-money boundary;
2. eight-row readiness matrix using only the three approved status labels;
3. five-minute daily strict-health inspection;
4. separate production read-only, local, and Dashboard workflows;
5. L1/L2/L3 freshness contracts, including doorbell-versus-ledger semantics;
6. fee, slippage, fill, oracle, capital approval, and sustainability gaps;
7. symptom-driven troubleshooting for all required degraded states;
8. read-only-first recovery discipline and production-mutation boundaries;
9. command safety tiers with prerequisites and success interpretation;
10. truth hierarchy, offline checker, future pre-commit rule, and audit log.

The matrix records L1 snapshot and observation tools plus the live neg-risk
input as verified; the L1-to-L2 chain, L2 mirror, and Dashboard as conditional;
and L3 plus automatic real-money execution as unavailable. Dynamic readiness
continues to defer to `.planning/CURRENT.md` and current production evidence.

## Verified Repository References

- Make commands are checked against the current Makefile, including the new
  `docs-m1-check` entry.
- All local links resolve to CURRENT, learning documents 07-11, the learning
  index, and the E2E acceptance guide instead of duplicating those sources.
- Health markers resolve to L1 snapshot age and L2 cursor lag, WS business-frame
  age, mirror age, and L3 active count in their implementation files.
- Dashboard markers resolve to `/status`, `/candidates`, `/signals`, and
  `/l3/[asset_id]` filesystem routes.
- The manual explicitly distinguishes strict `/health` from always-200
  `/healthz`; reachability is not presented as business readiness.

## Safety Boundary

The manual states twice that M1 output does not constitute real-money order
authorization. It also names the missing fee, slippage, fill, oracle,
risk/capital-approval, and sustainable-return evidence and classifies restart,
deploy, secret changes, and chaos as production mutations.
