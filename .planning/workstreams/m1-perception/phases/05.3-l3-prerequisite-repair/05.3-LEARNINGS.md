# Phase 05.3 Learnings — L3 Prerequisite Repair

## Decisions

1. `markets_latest` durably projects both outcome tokens through add-only
   Alembic 006; runtime Gamma lookup was rejected.
2. L2 `asset_id` is explicitly treated as the Yes token ID at the promoter
   boundary.
3. Observation coverage uses a deterministic 100-row seed; promotion keeps the
   original spread/depth/recency/N=5 gate.
4. Identity defects under-fill rather than synthesize fallback tokens.
5. Diagnostic planning and mutation application share one function with an
   explicit default-true apply boundary.

## Lessons

- A downstream strict selector cannot repair upstream sampling bias.
- Schema-shaped mocks can hide production contract bugs when they invent columns.
- A binary market is not fully identified by the token currently carrying TOB.
- “No-op consumer” does not make a function dry-run if another write-through
  remains inside the same call.

## Patterns

- Separate observation coverage from qualification thresholds.
- Persist identity once at L1 and reuse it downstream.
- Treat successful-but-incomplete data as under-fill; reserve LKG freeze for
  transport/outage failures.
- Test dry-run by asserting absence of every mutation category, not just its
  most visible side effect.

## Surprises

- Production had 583 liquid mid-band markets while all three active candidates
  came from one near-end event.
- A 100-book read-only sample produced 86 unchanged-recipe matches, so threshold
  relaxation was unnecessary.
- The documented dry-run could write `l3_promoted_at_ts` even with a no-op WS
  consumer.

## Open production gate

Local verification cannot establish production readiness. Alembic 006, a new
L1 mirror snapshot, L1/L2 deployment, `l3:active_count == 10`, real book-level
writes, and the fresh 24-hour Phase 05 soak remain separate steps.

## Adversarial self-check

1. If `l3-seed` finds 100 markets but only four complete token pairs qualify,
   why must strict health remain below `10/10`?
2. Why is lowering the spread threshold before expanding observation coverage a
   confounded experiment?
3. If a dry-run avoids WS calls but updates `l3_promoted_at_ts`, what false
   operational conclusion can the next health check report?
4. Why is `l2_top_of_book.asset_id` a Yes token here rather than a market ID?
5. Which evidence would distinguish local reachability from production readiness?
