# Plan 05.6-09 Summary: Generation-aware source truth fallback

## Root cause

The live certified Quote feed referenced generation snapshot 886, but the
legacy source-truth reader reported its last complete snapshot as 845. Its
incomplete coverage was treated as a hard opportunity-feed rejection even
though the feed carried a fresh, matching authenticated identity.

## Delivered

- Treat an explicit incomplete source-truth result as the same fail-soft input
  as a read exception.
- Reuse the existing authenticated fallback, which requires exact run, source
  snapshot, universe hash, source-truth hash, and freshness bounds.
- Preserve read diagnostics as `last-known-authenticated`; this is visible
  degraded source truth, not a fabricated live success.

## Verification

- Red/green contract test covers a stale legacy source truth beside a fresh
  certified generation feed.
- Opportunity endpoint suite: 27 passed; Ruff passed.

## Remaining production gate

Deploy and query the public endpoint for a run ID and candidate payload, then
continue the bounded generation-cleanup child repair before final acceptance.

## Follow-up: monitor-of-monitor closure

The Fly `cron` Polywatch machine was later observed in `stopped` state.  This
is an L1 incident: its local state and alert delivery disappear together, so
the resident watcher cannot be evidence of its own liveness.  Follow-up
`resident_watchdog.py` now runs outside that failure domain in GitHub Actions
and as the post-deploy gate.  It requires exactly one `cron` machine in
`started` state, starts and re-reads a stopped machine, sends an explicit L1
Critical Telegram incident, and fails on missing/duplicate machines, failed
repair, failed verification, or failed delivery.  The external schedule is
five minutes (best-effort provider cadence, not a timing SLA); Fly remains the
two-minute primary watcher.
