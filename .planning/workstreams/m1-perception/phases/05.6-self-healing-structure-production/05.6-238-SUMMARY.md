# 05.6-238 Summary — Fence publication pointer lineage

## Outcome

- Added `PublicationPointerConflictError` to distinguish a superseded candidate
  from transient provider/database failure and from an incomplete fan-in
  barrier.
- Quote generation admission now freezes the then-current predecessor into the
  immutable certifier identity. Certification updates `quote:current` only when
  the live pointer still equals that predecessor; legacy unfenced work cannot
  replace an existing current pointer.
- Idempotent admission replay preserves the original frozen lineage instead of
  recomputing it from a later pointer.
- Explicit Structure shadow publication now carries its observed predecessor
  into the pointer transaction. Opportunity certification rejects a lease whose
  Quote generation is no longer current.
- Quote and Opportunity workers terminally quarantine superseded attempts in a
  lease-fenced transaction with a warning incident, Dashboard alert,
  `publication.superseded`, and delayed/non-breaking qualification semantics.
  They create no retry circuit.
- Added a three-node `publication-pointer-conflict` disposable adapter proving
  stale Structure, Quote, and Opportunity publishers cannot move current truth;
  exactly one matching current success fact remains.
- Added isolated-database harness, Make entry, exact argv contracts, climb gates
  and the learning FAQ.
