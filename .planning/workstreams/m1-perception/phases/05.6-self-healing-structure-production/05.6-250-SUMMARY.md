# 05.6-250 Summary — Terminalize normal CLOB book disappearance

## Outcome

- `TransactionalQuoteBatchWorker` no longer classifies a successful CLOB response
  that omits a requested book as a retryable infrastructure failure. It commits
  the existing canonical `missing-book` terminal quote and preserves the actual
  provider response count for audit.
- Opportunity projection safety is unchanged: any non-executable leg clears the
  prepared set for its complete neg-risk group, so no incomplete group can become
  an Opportunity.
- The `clob-missing-leg` commissioning attack now proves one call, one terminal
  receipt, zero retry incidents and zero circuits. The genuinely transient
  `clob-429` attack owns an explicit, separate durable-backoff recovery path.
- The canonical Makefile entry describes that exact terminal-evidence contract;
  operators are no longer told to expect an impossible complete-coverage retry.
- The deterministic climb gate assertion was brought back into parity with the
  complete/resumable commissioning tests already present in the gate definition.

## Production diagnosis

- Exact read-only reproduction against batch 100 of Structure generation
  `52722c3014cdb6336fe840da6ffbfe6def5abade5e7f086aa2d2c344669c0c36`
  requested 500 books and received 419.
- Its first missing token mapped to Gamma market `3945442`, which was
  `closed=true` and `acceptingOrders=false`. The frozen Structure source pages
  were collected on 2026-08-29 but recovered and published on 2026-08-30.
- The prior policy therefore exhausted all 146 batch retry budgets and opened
  146 circuits for a permanent market-lifecycle condition. This is deterministic
  non-convergence, not provider jitter.

## Verification

- TDD regression was red on `IncompleteQuoteBatchCoverageError` before the code
  change and green afterward.
- Quote worker suite, both CLOB commissioning attacks, climb gate contract, Ruff
  and Pyright pass.
- The wider Quote/Opportunity/commissioning/runtime suite passed all tests except
  the inherited CLOB-429 commissioning coupling; after separating that recovery
  implementation, both affected real-database attacks pass.

## Production boundary

- No production database row, circuit, Machine, pointer, credential or recovery
  action was mutated by this code change.
- The running exact `e17f1359` image still has the old retry behavior. Production
  remediation requires a new exact image, complete commissioning, controlled
  rollout, and an explicitly evidenced release of the already-open old circuits.
