# 05.6-231 Summary — Prove expired-worker reclaim recovery

## Outcome

- Added a cleanup-safe `worker-exit` commissioning adapter for all eight M1
  production nodes. It stops the disposable worker after its real claim and
  durable progress, without directly modifying lease or runtime timestamps.
- One microsecond before the persisted lease deadline, `RuntimeReconciler` must
  return `job.heartbeat-missing-fence` with no action. One microsecond after the
  deadline, it must return the exact `job.heartbeat-missing -> reclaim-job`
  decision; premature reclaim is therefore an explicit test failure.
- The real `RecoveryExecutor` retires epoch 1 as
  `RecoveryLeaseExpired/retryable`, clears its owner and schedules immediate
  retry. The exited owner then executes the same terminal business API and must
  receive `StaleLeaseError` with zero success effects.
- A distinct worker claims epoch 2 and completes the same prepared transaction.
  Its runtime success and business postcondition resolve the critical incident
  without requiring process or Machine restart authority.

## Executable workflow

- Extended the shared isolated harness with `worker-exit` while preserving one
  migrated database per node and unconditional owned-resource cleanup.
- Added `make m1-production-commissioning-worker-exit`, guarded by an explicit
  loopback test DSN and exact release/config identity. It has no production
  fallback, node-skipping CLI or all-run timeout.
- Registered H-044 and added the eight-node adapter, isolated one-node harness
  and exact Make argv cases to the deterministic production-enablement profile.

## Qualification boundary

- The runtime recovery decision retains the historical field
  `qualification_breaking=true` for a critical expired-owner incident. The
  qualification service maps that event to `incident.p1-slo`, which is a
  blocking reason: healthy seconds pause and prior coverage remains intact.
- It is not one of `BREAKING_REASONS`; worker loss therefore cannot invalidate
  the epoch. Only the closed truth/fence/integrity/identity reasons do that.
- Successful epoch-2 business completion emits the recovered incident fact that
  releases the block and permits healthy-second accumulation to resume.

## Boundary

- No production database, provider, Fly deployment, Machine, SSH, Docker
  context or Colima operation is part of this plan.
- Ruff, production-source Pyright, eight real-node tests, isolated harness and
  command contracts pass. Exact-HEAD guard and H-044 climb confirmation follow
  the commit.
- With worker-exit implemented, all five shared eight-node attacks now have
  executable adapters. The next exact image should run them together under one
  immutable release/config before node-specific canaries or qualification.
