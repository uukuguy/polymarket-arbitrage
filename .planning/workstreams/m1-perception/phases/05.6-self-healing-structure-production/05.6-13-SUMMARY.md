# Plan 05.6-13 Summary: Structure incident operator visibility

- The production `structure-producer-failure` lifecycle now has a typed
  `/perception/incidents` diagnosis, so the existing Fly incident console shows
  P1 severity, stale-market-map impact, automatic bounded retry, failure reason,
  elapsed time/stage where available, and an explicit operator action.
- A parent-side `database is locked` failure is intentionally actionable even
  when no child stage or elapsed time exists; missing child telemetry is rendered
  as unavailable rather than suppressing the entire P1 card.
- Closing a Structure incident requires the matching post-failure durable
  `snapshot_attempts` success receipt. Incident storage failures are fail-soft
  relative to a certified snapshot and cannot turn that snapshot into a failed
  scheduler attempt.
- RED/GREEN coverage validates the operator API for timed and parent-side
  failures, receipt-gated lifecycle verification, and scheduler callback
  isolation. Focused tests and Ruff pass; deployment still requires exact Fly
  release and live API verification.
