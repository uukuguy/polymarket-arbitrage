# 05.6-70 Summary — Fenced M1 job repository

## Delivered

- Added `polyarb.control_plane` models and a caller-owned synchronous psycopg
  repository for durable M1 job coordination.
- `claim_job` uses `FOR UPDATE SKIP LOCKED`, advances a lease epoch on every
  claim (including expired-lease takeover), and creates an attempt receipt.
- Heartbeats, checkpoints, and terminal transitions require the current
  `(job_key, lease_owner, lease_epoch, state='leased')` fence; stale writers
  get `StaleLeaseError` instead of corrupting the new owner's progress.
- Checkpoint idempotency authenticates the original receipt and retains the
  last committed cursor across retry. Quarantined work is never claimable.
- Incident event creation and one outbox row per channel are committed in the
  same transaction; repeated event keys return the original event rather than
  emitting duplicate alerts.
