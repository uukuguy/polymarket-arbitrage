# 05.6-218 Summary — Commission every production node before qualification

## Outcome

- M1 now has a machine-readable pre-qualification contract covering the exact
  eight-node Structure→Quote→Opportunity runtime DAG.
- Eighteen directed attack contracts expand to 66 required node-level proofs.
  Every proof requires injection, detection, recovery start, recovery, cleanup
  and a business postcondition under one exact release/config identity.
- Qualification v2 counts 86,400 healthy effective seconds. Expected faults
  pause or block the same epoch; only serious truth, fence, integrity or
  identity defects invalidate accumulated history.
- Operator status exposes `eligible`, `paused`, `blocked`, `invalidated` or
  `qualified` plus the exact reason.

## Design correction

- A long production window cannot be the first place known integration faults
  are discovered. Commissioning is the readiness gate; qualification is the
  sustained-operability gate.
- Ordinary incidents and circuit activity map to `recovery.started`; contained
  or confirmed recovery resumes accumulation. Evidence gaps, freshness/SLO
  failures and recovery budget failures block without erasing prior healthy
  seconds.
- Automatic comparison of unscoped progress/success counters across unrelated
  runtime sources was removed. Only an explicit producer-scoped
  `progress.regressed` fact invalidates an epoch.
- Legacy v1 epochs have no persisted eligibility fields. Replay/status derive
  `recovering` as blocked (and terminal states from their state) so an existing
  recovery row cannot conflict with the v2 projection during restart.

## Interfaces

- `make m1-production-commissioning-plan` prints the closed, read-only node and
  attack manifest.
- `make m1-production-commissioning-verify evidence=<json>
  expected_release=<sha> expected_config=<sha256:id>` fails closed unless every
  normal turn, exact attack proof, cleanup, postcondition and final lineage is
  present.
- Eligibility state/reason reuse the existing qualification `slo` JSON, so no
  schema migration or manual production data mutation is required.

## Verification

- Eight commissioning contract tests pass, including missing proof, lifecycle
  ordering, exact identity, CLI and Make entry points.
- Qualification, service, Postgres replay/identity, dashboard/API and runtime
  fault-matrix integrated tests pass with the v2 semantics.
- Runtime fault matrix focused verification passes 15/15. Ruff and Pyright pass
  on all changed Python modules and tests.
- Two TDD compatibility regressions first proved legacy `recovering` rows were
  incorrectly defaulted to eligible, then passed after state-derived fallback
  was shared by runtime replay and operator status.
- `make planning-status` passed before closure; the exact-HEAD full M1 gate is
  deliberately deferred until the implementation and summary share one commit,
  because the image contract correctly rejects dirty runtime inputs.

## Production boundary

- This plan defines and verifies commissioning evidence; it does not fabricate
  or claim the 66 live proofs. Attack adapters and controlled execution are the
  next production task.
- No production Machine was deployed, restarted or accessed through SSH. No
  database row was manually changed. Production remains on the prior stopped
  diagnostic boundary; the unrolled v24 image is obsolete.
- The next exact image will be built through OrbStack only. A new qualification
  epoch cannot start until exact-image/disposable attacks, named provider
  canaries, cleanup and final lineage all verify ready.
