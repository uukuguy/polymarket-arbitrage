# 05.6-229 Summary — Prove retry-budget circuit recovery

## Outcome

- Added a cleanup-safe `retry-budget-exhaustion` commissioning adapter for all
  eight M1 production nodes. It injects the same typed validation failure
  through the public retry API until the node's shared policy budget is
  exhausted; it does not age leases or edit circuit rows directly.
- The first two failures schedule policy-owned backoff. The third identical
  failure opens the durable circuit while all three failed epochs remain
  retryable and produce one deduplicated retry incident.
- At the persisted probe deadline an ordinary worker is explicitly denied a
  lease. `RuntimeReconciler` must then classify the candidate as the
  non-breaking `circuit.probe-due -> probe-circuit` decision, and the real
  `RecoveryExecutor` must complete that exact fenced action.
- Only after probe release may epoch 4 claim and complete the same prepared
  business transaction. Its success closes the circuit, clears the fingerprint
  and probe deadline, resolves both retry/recovery incidents and produces the
  node-specific business postcondition.

## Executable workflow

- Extended the shared isolated harness with the `retry-budget` command while
  preserving one migrated database per node and unconditional owned-resource
  cleanup.
- Added `make m1-production-commissioning-retry-budget`, requiring an explicit
  loopback-only test DSN plus exact release/config identity. It has no
  production fallback, node-skipping CLI or all-run timeout.
- Registered H-042 and added the eight-node adapter, isolated one-node harness
  and exact Make argv cases to the deterministic production-enablement climb
  profile.

## Chain-truth evidence

- Eight real-PostgreSQL node tests prove attempt epochs 1–3 are retryable with
  `CommissioningValidationFault`, while epoch 4 alone succeeds.
- Each test proves circuit state `3/open` before recovery, one deduplicated
  retry incident with `attempt-failed`, `attempt-failed`, `circuit-opened`, then
  `recovered`, and one completed successful `probe-circuit` action.
- The final database facts prove circuit state `0/closed`, no next probe or
  failure fingerprint, resolved incident state and a causal business
  postcondition from the successor epoch.

## Boundary

- No production database, provider, Fly deployment, Machine, SSH, Docker
  context or Colima operation is part of this plan.
- The dirty-tree exact-image guard intentionally rejected the uncommitted
  release inputs while all other grouped regression cases passed. It must pass
  on committed HEAD before H-042 confirmation.
- A new exact image is intentionally deferred until the remaining shared
  heartbeat/worker-exit adapters are confirmed, so all attacks can be rerun on
  one immutable release/config for the eventual combined envelope.
