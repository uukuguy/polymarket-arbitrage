# 05.6-235 Summary — Diagnose and recover a missing Quote admission shard

## Outcome

- Added `QuoteAdmissionShardUnavailable`, a typed boundary error carrying only
  the manifest-authorized Structure artifact key. Quote admission incidents now
  name the exact missing shard without including provider response bodies,
  credentials or arbitrary exception detail.
- Added a disposable `quote-admission-missing-shard` adapter. It creates a real
  two-shard Structure v3 manifest, completes the public normalize/certify chain,
  then withholds one manifest-named shard from the actual
  `TransactionalQuoteAdmitter`.
- The first admission attempt becomes retryable through the existing fenced
  circuit/incident transaction. It records one warning incident and Dashboard
  alert with the safe missing key while committing zero Quote batch inputs,
  batch jobs, admission checkpoints or Quote pointer effects.
- Restoring that exact object and advancing only to the shared retry policy's
  persisted due time lets epoch 2 read both shards, upload one authenticated
  Quote batch artifact containing two legs, commit admission and resolve the
  original incident. Quote certification remains a separate downstream step.

## Authority and recovery boundary

- The Structure shard manifest is immutable authority for allowed artifact
  keys/digests. The object boundary may report one key unavailable, but cannot
  substitute another key, leak provider content or mutate the manifest.
- V3 Quote batch inputs remain artifact-backed: PostgreSQL stores key, digest
  and `leg_count=2`; it intentionally does not duplicate `legs` or `token_ids`.
  Commissioning verifies the stored reference against object HEAD metadata.
- No private job, lease, receipt, incident, pointer or clock mutation is used.
  The barrier has no timeout; retry timing comes only from `RuntimeRetryPolicy`.
