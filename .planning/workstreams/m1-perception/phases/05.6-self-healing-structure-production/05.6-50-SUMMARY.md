# 05.6-50 Summary — restart-safe Quote attempt recovery

## Outcome

Production evidence showed a rolling deployment could abandon a Quote child
after it had checkpointed `persist`. Startup recovery correctly failed the
collecting Quote run but left the matching `neg_risk_quote_attempts` row in
`collecting`; Dashboard therefore displayed a false live persist stage until a
future admission aged it out.

`NegRiskQuoteStore.recover_orphaned_collection_state()` now atomically fails
both sides on worker start: attempts become
`failed/worker-start-orphaned`, and runs become
`failed/collector-orphaned-on-worker-start`. The production Quote worker uses
this single recovery primitive before its first admission.

## Verification

- RED test reproduced the abandoned live attempt/run pair.
- Store recovery and full Quote worker regression suite passed.
- Changed-file Ruff and diff check passed.

## Production follow-up

Deploy once without overlapping releases. Verify the existing `878`-style
orphan never recurs: after any restart the console must show a terminal
attempt immediately, then the supervised producer's next admission. Keep all
P1 incidents open until a post-recovery certified Quote and Structure chain
proves recovery.
