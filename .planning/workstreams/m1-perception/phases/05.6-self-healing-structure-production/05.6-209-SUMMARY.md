# Plan 05.6-209 Summary: Runtime Lifecycle Hardening

**The local runtime no longer lets unrelated timeout layers kill the same
attempt. All eight job types now share one persisted policy, long reducers
resume from durable ordered checkpoints, service stop is bounded and
observable, and reclaim/circuit/qualification transitions have real PostgreSQL
end-to-end proof. Production rollout and the new 86,400-second epoch remain.**

## Root cause

Plan 208's 3,600-second Structure deadline fixed one symptom but a second
production failure proved the defect class was broader: `quote-admit` owned a
valid long attempt yet the coordinator cancelled its turn at 105 seconds. The
cancel bypassed normal finalization, left `running` attempts, and restarted all
231 shards from zero. Structure certification had the same zero-restart shape
over 1,117 ranges.

The audit found competing module-local policies, scheduler/role timeouts,
relative I/O budgets that reset on every call, no shutdown grace consumption,
timestamp-ordered checkpoints, an expired-lease reclaim gap, an open-circuit
decision-order contradiction, and new qualification releases replaying old
ledger history as if it were current evidence.

## What changed

- `runtime-v2` covers exactly the eight registered job types. It derives and
  validates lease, heartbeat, progress, absolute attempt, I/O, terminal grace,
  retry budget and checkpoint cadence. Claim persists the exact profile;
  migration defaults are dropped after backfill so future writers fail closed.
- Async runtime watchdogs enforce absolute attempt and no-progress deadlines.
  Structure's synchronous range calls consume remaining absolute attempt time
  instead of resetting a full timeout per operation.
- Scheduler lanes come from a validated acyclic DAG, run independently, and no
  longer own a turn timeout. Both multi-role and role-local services stop new
  claims, request/cancel current work, drain through central terminal grace and
  emit `service-stop-grace-expired` when durable takeover must finish recovery.
- Sync workers run through a daemon bridge so Python's default executor shutdown
  cannot turn one non-cooperative call into an infinite process join. Production
  workers still use client bounds, stop checks, checkpoint facts and epoch
  fencing; daemonization is not treated as data safety.
- `claim_job` closes an expired old attempt and appends the authoritative
  retryable event before creating a new epoch. Revision 028 also repairs legacy
  current leased jobs that have no matching runtime row.
- Running checkpoints receive a locked per-job numeric sequence. Structure
  certification checkpoints every 25 ranges and Quote admission every 10
  shards, with generation/digest/policy verification before resume.
- Open circuits are reconciled before their historical attempt clocks. Ordinary
  workers cannot auto-claim a due circuit; the recovery controller releases one
  probe and advances `next_probe_at`.
- Qualification's first identity consumes current breaker history. A later
  release detects an existing predecessor identity and seeds its cursor at the
  live ledger high-water, so old facts cannot count as new release coverage.
- Revision 026's PostgreSQL 16 downgrade SQL was repaired for dynamic database
  identifiers and composite row declarations; revision expectations now point
  to the real head 028 without restoring broad `service_role` certificate
  authority.

## Verification evidence

- Real PostgreSQL circuit chain: three failures, open circuit, ordinary claim
  denied, reconcile/schedule/execute `probe-circuit`, exactly one released claim.
- Real 027→028 migration: current leased orphan plus running attempt becomes
  retryable with bounded error evidence; all five runtime policy defaults are
  absent; 028→027→028 round trip passes.
- Production-shaped resume: 1,117 Structure ranges and 231 Quote shards resume
  after the last numeric checkpoint; stale epoch and mismatched proof fail.
- Non-cooperative sync and stalled async terminal tests prove both service loops
  return through terminal grace and emit immediate observable evidence.
- Full `make test-m1`: **3,947 passed, 1 skipped, 1 expected xfail** in
  1,519.17 seconds. The large 120k/166,926-row performance/golden group completed
  naturally rather than being killed by an arbitrary wrapper timeout.
- Complete PostgreSQL control-plane file passes. Focused revision 026/028,
  runtime, scheduler, checkpoint, circuit and qualification suites pass.
- Ruff check for every changed Python file, format check for Plan 209 files,
  `git diff --check`, `make planning-status`, and `make climb-check` pass.
- Independent review rounds closed all three HIGH findings. The only subsequent
  MEDIUM (missing role-local grace-expired emission) was fixed with a regression;
  no CRITICAL/HIGH finding remains.

## Production boundary

Coordinator Machine `e82d1220b2d138` and qualification Machine
`876077f0274598` remain stopped. Revision 028 has not been applied and no worker
has been restarted on the uncommitted code. The earlier Plan 208 rollout request
is superseded because its image and no-schema-mutation envelope do not contain
this repair.

The next rollout must build one immutable image from the committed Plan 209
state, verify revision/image/CLI contracts, apply revision 028 before workers,
preserve existing Machine IDs and non-image configuration, then start the
coordinator and qualification in sequence. Live proof must reach Structure,
Quote admission, Quote certification and opportunity terminal publications
without zero restart or orphan attempts. Only then may a new 86,400-second
qualification window begin.
