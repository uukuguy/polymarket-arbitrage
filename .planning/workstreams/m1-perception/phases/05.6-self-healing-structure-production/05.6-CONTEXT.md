# Phase 05.6: Self-Healing Structure Production - Context

**Gathered:** 2026-07-31
**Status:** In progress
**Source:** H-011 production RCA and user requirement for continuous recovery

## Production failure

The deployed monolithic Structure subprocess repeatedly timed out in
`gamma-events` near its 240-second parent deadline. The scheduler accumulated
failures, entered terminal `PAUSED`, Structure became about 3.7 days stale,
Quote accumulated roughly 1,977 failures, and the opportunity route returned
HTTP 503. An old complete snapshot remaining readable did not make this a
healthy production state.

## Locked decisions

- Persist one opaque Gamma page and its successor cursor in one SQLite
  transaction.
- Resume the same open window after subprocess timeout or daemon restart.
- Publish no staged facts until both events and markets are complete and the
  existing production validator certifies the window.
- Preserve bounded live point lookups for event-membership reconciliation.
- Treat repeated failure as visible `RECOVERING`, never as a terminal producer
  stop; retry after a short bounded delay.
- Expose window state and page progress through strict `/health`.
- Keep Archive and CLOB outside Structure production.
- Production acceptance requires exact release identity, fresh Structure,
  matching Quote, opportunity HTTP 200, and observed continuation after
  recovery. Local tests are deployment prerequisites, not production evidence.

## Safety boundary

Public Gamma/CLOB reads and the existing local SQLite volume only. No wallet,
signing, orders, balance mutation, or real-money authorization.
