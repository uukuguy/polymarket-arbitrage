# 05.6-217 Summary — Keep transient heartbeat outages inside the lease boundary

## Outcome

- A temporary PostgreSQL heartbeat failure no longer converts a healthy,
  still-running payload into an unbounded no-heartbeat drain.
- Synchronous Structure work and asynchronous attempt runtimes retry only the
  typed transient heartbeat class, then restore the normal cadence after a
  successful renewal.
- Success paths cannot cross into a terminal fenced commit while a heartbeat
  renewal is in flight or awaiting retry.
- No lease, attempt, progress, statement, lock, process, or test timeout was
  enlarged. M1 remains OrbStack-only; Colima is neither required nor used.

## Production root cause

- The exact v23 Structure probe for the last open target successfully claimed
  an attempt and entered `normalize-range`, then stopped heartbeating while its
  large events payload continued computing. Its persisted lease and heartbeat
  deadlines elapsed without a process restart.
- `_run_bounded_sync_call()` treated every heartbeat exception as terminal,
  but its no-late-effect contract still drained the underlying future. A
  transient PostgreSQL connection `OperationalError` therefore disabled all
  later heartbeat opportunities while payload work continued.
- This was not a missing wrapper and was not fixed by increasing a timeout.
  It was a contradictory lifecycle transition between renewal failure,
  payload drain, and lease ownership.

## Repair

- `PostgresControlPlane.heartbeat_runtime_attempt()` maps only psycopg
  operational failures to secret-safe `RetryableHeartbeatError`; stale fences
  and business-contract errors retain their immediate-failure semantics.
- Retry cadence is derived from the existing policy as
  `heartbeat_seconds / 3`. A successful renewal restores the normal heartbeat
  cadence.
- `AttemptRuntime` checks its locally known persisted `lease_expires_at`
  before any renewal call and raises typed `LeaseDeadlineExceeded` at the
  boundary. The existing absolute attempt deadline remains authoritative too.
- Sync calls retain their no-late-effect drain for fence/deadline/cancellation
  errors. If payload finishes while renewal is pending, it waits for current
  lease proof before returning.
- Async success stop similarly retains an in-flight or retry-pending heartbeat
  until renewal succeeds. Error/cancellation exits drain only already in-flight
  work because they do not enter a terminal mutation.

## Verification

- TDD regressions cover blocked Structure reads, transient heartbeat recovery,
  derived async retry cadence, local lease expiry, stale-fence cancellation,
  and the success-stop race.
- The full transactional Structure, Quote, Structure source, admission,
  opportunity, runtime coverage, and PostgreSQL contract suites pass.
- Real PostgreSQL lock and statement timeouts roll back liveness mutations and
  surface the typed retryable wrapper with their original class retained only
  as the cause. Provider/error text is not rendered by the wrapper.
- Ruff and Pyright pass for all changed production modules.
- A pre-commit full M1 run reached 4,109 passed, one skipped, and one expected
  xfail. Its sole failure was the exact-image Makefile guard correctly refusing
  dirty runtime inputs. The exact-HEAD full gate must run after this summary
  and implementation become one commit.

## Production boundary

- No production database row was manually edited and no resident low-memory
  Machine was accessed through SSH.
- The resident controller, qualification, and Structure Machines remain
  stopped at the prior diagnostic boundary. The v23 qualification window is
  invalid and will not be resumed.
- This repair requires a new exact v24 image. Production recovery and a fresh
  86,400-second qualification identity start only after the exact-HEAD gate,
  independent OrbStack image inspection, and controlled rollout pass.
