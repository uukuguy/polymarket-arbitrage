# 05.6-38 — Dashboard retained Incident recovery chain

## Outcome

Open P1 Incident cards remain inspectable after raw lifecycle event compaction.
`GET /perception/incidents/{id}/history` now falls back to the independently
hash-validated `open_authority` row when that identity has no retained raw
events, returning its current state with `history_complete=false` rather than
404.  The result deliberately uses event ID `0` as an explicit non-event
marker; it never fabricates a SQLite lifecycle ID.

Supported Quote incidents that are still `contained` because they predate the
current recovery writer contract now transition to `recovering` on a new
certified Quote run.  That run cannot verify itself: the next certified run
must supply the post-recovery writer receipt before terminal `verified`.

## Why

Production showed open Structure and Quote P1 cards whose exact-ID history
returned `incident-not-found-or-retained`.  A fresh Quote run simultaneously
proved a healthy feed while an older Quote timeout remained `contained`, which
the previous certified-success handler ignored forever.  Both conditions made
the Dashboard incomplete as an on-call control plane.

## Safety contract

- Unknown IDs and closed/fully-retained identities still return 404 exactly as
  before.
- Only current open authority may supply the compacted fallback, and its hash
  is validated before it is exposed.
- A compacted prefix is never claimed complete.
- Only explicitly supported Quote fault kinds can gain the recovery boundary;
  unrelated legacy rows remain untouched.
- `verified` still requires a writer mutation after the new `recovering`
  event; no P1 is manually or retrospectively cleared.
