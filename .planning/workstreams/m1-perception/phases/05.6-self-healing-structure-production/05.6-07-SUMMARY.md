# Plan 05.6-07 Summary: Checkpoint-aware strict health

## Root cause

After generation read activation, strict health falsely failed while the next
Structure generation checkpoint was active. It treated a `building` snapshot as
`FAILED`. Separately, a drift subprocess that wrote the durable terminal seal
just before its hard timeout remained the latest failed attempt and overrode
that same authenticated receipt.

## Delivered

- `building` is projected as active (`BUILDING`, pass); truth freshness and the
  durable publication checkpoint remain independent gates against a stuck run.
- A failed drift attempt is superseded only when the current authorized seal
  has the same non-empty comparison id. Unrelated or identity-less failures
  remain strict failures.

## Verification

- Red/green tests cover an active building snapshot, a terminal seal that
  supersedes its own timeout, and the missing-comparison-id rejection boundary.
- Full health endpoint suite completed without failure output; changed-file
  Ruff passed.

## Remaining production gate

Deploy and verify strict `/health` passes from generation snapshot 884 while
the new publication checkpoints normally. Quote remains disabled until explicit
activation and real candidate/notification validation.
