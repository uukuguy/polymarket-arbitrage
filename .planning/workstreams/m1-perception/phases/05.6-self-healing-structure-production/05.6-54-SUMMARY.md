# 05.6-54 Summary — bounded Quote staging chunks

Quote terminal rows now enter an already-invisible `collecting` run in 500-row
SQLite transactions.  Each transaction validates only its own token subset,
avoiding repeated 41k-row run-leg scans.  The collector persists
`persist_chunks` and `persisted_quotes` after every committed chunk.  The
existing `complete_run` remains the sole cardinality/receipt/current-pointer
certification boundary; no collecting or failed staging row becomes an M2 or
opportunity API input.

Verification: red/green staging visibility test, red/green current-chunk SQL
lookup test, and focused Quote store/collector/worker regression are required
before deployment.  Production proof must show a new complete Quote run,
live opportunity response, visible chunk progress, and a recovered incident
lifecycle; it must not treat routing health alone as acceptance.
