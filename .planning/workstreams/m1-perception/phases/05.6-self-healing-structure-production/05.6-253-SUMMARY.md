# Plan 05.6-253 Summary: Single-Process Runtime Recovery

The runtime controller can now perform an exact production recovery without
hosting a second Python interpreter or relying on an arbitrary SSH timeout.

## Root cause

Three SSH diagnostics/recovery attempts on the 256MB controller created a second
roughly 126MB Python process beside the resident daemon. Fly recorded exit 137
with `oom_killed:true`. Temporarily resizing to 512MB made one action succeed,
but did not fix process ownership. Production testing also exposed three sequence
errors: fixed maintenance owner identity caused a uniqueness conflict, stopped
process state was mistaken for action success, and a circuit probe can be
legitimately deferred while its persisted worker lane is busy.

## What changed

- The local renderer now creates a full optimistic Machine update that preserves
  image, VM shape, environment authority and shutdown contract while replacing
  the resident daemon with one exact target/action process and restart policy
  `no`.
- Restore rendering requires the saved baseline, the fresh maintenance Machine,
  and the original maintenance payload. Any ID, region, version or config drift
  fails closed.
- `runtime-reconcile-until` retries only the typed worker-lane-busy result, once
  per second for at most 45 seconds. Its controller lease must outlive that
  budget. Success remains exactly one fenced action.
- A separate verifier compares before/after control-plane artifacts and requires
  one new exact `completed/succeeded` action. Exit code, stopped state and log
  presence are not accepted as business postconditions.
- Makefile exposes every new command. The operator obtains a fresh short-lived
  Fly token before each cloud mutation rather than caching one for a multi-target
  batch.

## Verification

- Unit and contract tests cover process replacement, exact restore, identity
  uniqueness, lane-busy retry, non-retryable state rejection, outcome proof and
  Makefile wiring.
- Ruff and Pyright pass for changed production files.
- Production proved the original 256MB path no longer OOMs and exact restore
  returns the controller to its digest-pinned observe-only baseline.
- Production also falsified “stopped means succeeded” and “all probes can be
  released together”; both are now explicit fail-closed contracts.

## Production boundary

Structure is running on the previously deployed exact digest. Two stale
Structure circuits have been closed through verified successor attempts; three
remain. The bounded lane-wait command requires a new exact image before those
three are resumed.
