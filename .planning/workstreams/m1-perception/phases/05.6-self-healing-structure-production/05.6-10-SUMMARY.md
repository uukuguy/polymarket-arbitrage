# Plan 05.6-10 Summary: Quote timeout durable incident (Task 1)

- Added a Quote-owned durable incident lifecycle. A subprocess hard timeout
  records one `quote-collection-timeout` incident under `quote-collection`,
  with deadline, run/token identity when available, consecutive failures,
  last certified-success age, automatic action, and operator next action.
- Repeated timeouts update the same open incident rather than creating an
  incident storm. Retry remains `recovering`, not recovery.
- The production Quote worker now attempts this persistence fail-soft after
  timeout terminalization; a ledger write failure is logged but cannot mask the
  original collector failure.
- Focused worker, feed-health, and incident tests pass. API/Dashboard projection
  and certified-recovery proof remain the next tasks.

## Task 2-3: operator read model

- `/perception/incidents` now exposes a validated, credential-free Quote
  diagnosis object. The Dashboard renders impact, automatic action, next
  action, deadline, consecutive failures and last certified-success age from
  that exact durable record.
- Dashboard TypeScript typecheck and production build pass after restoring the
  lockfile-pinned dependencies. The certified recovery proof remains next.

## Task 4: recovery proof

- A Quote incident can now transition to `verified` only when the referenced
  durable quote run is `complete`, completed after recovery began and before
  verification, and has matching requested/successful counts. A retry or a
  stale former complete run cannot close the incident.

## Task 5: full-universe CLOB throughput

- Production evidence showed a 38,972-token Quote run entered `fetch` then
  exceeded its 100-second fetch budget while serially issuing roughly 78
  500-token CLOB calls. `ClobReaderClient.get_books` now issues chunks with a
  client-wide, configurable bounded concurrency (default 12), while retaining
  the existing global CLOB request-rate limiter and deterministic chunk order.
- `asyncio.gather` returns no partial result: one failed batch fails the whole
  quote collection, so the run remains atomic and cannot certify a partial
  M1→M2 feed. Focused CLOB tests prove the concurrency bound, ordering, and
  all-or-nothing failure behavior.
- The child CLI keeps its stdout JSON-only protocol at normal verbosity. This
  makes fetch-timeout envelopes reliably parseable by the parent even in
  embedded runners; detailed logging remains available via `--verbose`.
- `.dockerignore` excludes the independently deployed Dashboard and local
  superpowers workspace so remote Fly builds do not upload the 500MB+ frontend
  dependency tree before this backend-only deployment.
- A non-timeout child exit now logs and carries a bounded (1KB) stderr tail.
  This preserves the stdout JSON protocol while making the next production
  exception diagnosable instead of reducing it to `child-failed` byte counts.
- Non-timeout child exits also create a durable `quote-collection-failure`
  incident, visible in the same API/Dashboard diagnosis card with failure
  reason, retry-at-next-cadence action and stderr investigation path. A later
  certified complete Quote run verifies both timeout and non-timeout open Quote
  incidents through the same durable run proof.
