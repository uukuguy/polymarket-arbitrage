# Plan 05.6-16 Summary: Single-authority L1 deployment

- Fly v320 exposed that its default HA deployment path could leave two running
  `app` machines for a single-volume SQLite daemon. The unseeded machine had a
  different volume and independent Structure attempt/page history, making
  public reads non-deterministic between two market authorities.
- The unseeded machine `1851e36a946708` was stopped. The existing authority
  volume remains mounted only by `85e929f411e068`; health then showed durable
  Structure checkpoints and advancing page count from that source.
- `make deploy` and the GitHub deploy workflow now use
  `--ha=false --max-concurrent 1`, then explicitly converge to `app=1 cron=1`.
  This preserves the existing authority volume across future releases rather
  than creating a temporary unseeded SQLite replica.
- RED/GREEN deploy-contract tests cover both entry points. The operator manual
  documents the one-authority invariant, recovery evidence, and exact checks
  required if Fly ever reports more than one app machine.
