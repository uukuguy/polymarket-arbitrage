# 05.6-241 Summary — Exact v28 timeout-family image

## Outcome

- Built and pushed the non-deploying exact-HEAD runtime image
  `m1-runtime-v28-0f5dcc53` using command-scoped OrbStack local build mode.
- Registry digest is
  `sha256:c96209be0972b5e71a86c7e5ff419577d0bdce362f2b1b436c5e55d35c761d94`.
- Independent pull used a temporary `/tmp` Docker authentication directory and
  the explicit verified OrbStack socket; global Docker credentials and context
  were not changed.
- Image inspection proved linux/amd64, user `polyarb`, exact OCI revision
  `0f5dcc539c88be08851bf76956a51376803ba3c3`, local image ID
  `sha256:1aa058ca7b7f3e4a35953b1554d2f208c6bf1a244ce3862604dcb29f81bb3b7c`,
  and size 752,396,051 bytes.

## Boundary

- `flyctl deploy --build-only --push` created the immutable registry image; it
  did not deploy or mutate any Fly Machine.
- No production database/provider request, canary, SSH, qualification action,
  Docker global-context switch, Colima installation, or Colima execution
  occurred.
- The first isolated pull attempt exposed that `DOCKER_CONFIG` also hides
  context metadata. It failed before login/pull; the successful retry bound
  `DOCKER_HOST` directly to the already-inspected OrbStack socket while keeping
  registry auth temporary.
