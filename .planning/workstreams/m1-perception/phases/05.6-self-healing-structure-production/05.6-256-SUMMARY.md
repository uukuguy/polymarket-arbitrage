# Plan 05.6-256 Summary: Repair the Post-Publication Opportunity Path

Production timestamps falsified the earlier assumption that the 24-minute
Structure parity pass consumed qualification freshness. Structure was published
at 18:31:15, Quote at 18:42:35, and Opportunity at 18:46:19. The actual
post-publication critical path was 680 + 224 = 904 seconds, four seconds beyond
the unchanged 900-second product SLO.

The 224-second Opportunity step loaded 143 certified Quote batches serially.
`TransactionalOpportunityCertifier` now reads immutable batch references and
authenticated R2 artifacts in ordered waves. Production obtains the existing
`clob_batch_max_concurrency` authority (default 12, validated 1..32); constructor
default one preserves isolated adapters and tests unless they opt in.

The certifier still owns one lease and performs one terminal pointer publication.
The outer runtime synchronization continues lease heartbeat while a wave runs.
Each lane checks service stop before DB/R2 work, the executor drains started
siblings before returning, and `executor.map` restores frozen input order even
when reads complete out of order. Stop remains an interruption and does not
consume retry budget.

TDD proves 24 batches reach exactly six active reads, preserve leg and quote
order, reject zero or greater-than-32 concurrency, and leave no projection
threads behind. The complete Opportunity, CLI, and runtime-contract regression
set passes.
