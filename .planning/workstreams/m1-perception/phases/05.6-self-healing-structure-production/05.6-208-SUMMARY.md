# Plan 05.6-208 Summary: Qualification Publication Liveness

**The local repair removes the deterministic five-minute Structure certifier
restart loop and aligns Structure freshness with transactional publication
truth without expanding database authority. Production rollout and a new live
qualification epoch remain the next gate.**

> **Superseded before rollout by Plan 05.6-209.** Pre-rollout proof exposed the
> same zero-restart failure under a scheduler-owned 105-second timeout in
> `quote-admit`. Plan 209 replaces the isolated deadline adjustment with one
> runtime policy, resumable reducers, bounded stop and revision 028. The Plan
> 208 authorization performed no production mutation.

## Root cause

Production job
`structure:18daa4bd2efa3ea8a72b9b3994dfb8021dba39c6249a2299cb361c6ae8c8dec5:certify`
contains 1,117 ranges. Lease epochs 75 through 85 remained heartbeat-healthy
and progressed to ranges 286–297, but each crossed the generic 300-second
attempt deadline. Reclaim started the same non-checkpointed parity loop from
range one; attempt count reached 86 without a manifest commit.

Separately, qualification queried `structure:current`, while the transactional
Structure contract explicitly preserves that legacy pointer as absent. The
current Quote pointer already carries the Structure bundle digest used by the
published snapshot.

## What changed

- Runtime attempt creation now derives a job-aware deadline profile.
  `structure-certify` receives a 3,600-second absolute ceiling for the
  production 30-second lease. All other job types retain 300 seconds, while
  certifier heartbeat/progress remain 10/30 seconds.
- Qualification maps `quote:<digest>` to `structure:<digest>` and joins that
  exact certified manifest. Both Structure and Quote freshness require an exact
  lowercase 64-hex Quote generation identity; missing or malformed truth still
  returns no row and becomes `evidence.gap`.
- The query reads only `m1_publication_pointers` and
  `m1_generation_manifests`, both already in the deployed qualification
  capability. No migration, grant, compatibility pointer, or backfill was
  added.
- Chapter 92 explains the four runtime clocks and why qualification must follow
  consumed publication truth.

## TDD evidence

- Deadline test first failed because `runtime_deadline_profile` did not exist;
  after the minimal implementation, the certifier profile is 10/30/3600 while
  the normalizer remains 10/30/300.
- Freshness test first failed on the legacy `structure:current` query.
- A second RED exposed that the initial admission-table join exceeded the
  production qualification role. The final GREEN query maps Quote identity
  directly and explicitly rejects `m1_quote_admission_inputs`.
- Independent review found that two matching malformed manifests could bypass
  a substring-only join. Unit and real-PostgreSQL RED tests reproduced it; the
  exact generation regex now makes both Structure and Quote freshness emit
  `evidence.gap`.
- Focused runtime/reconciler gate: 163 tests passed.
- Combined transactional runtime, qualification, reconciler, and database-role
  gate: 131 tests passed.
- Plan 05.6-209 subsequently closed the revision-026 downgrade, scoped-role,
  runtime-head and lifecycle gaps. Its complete M1 run is 3,947 passed, 1
  skipped and 1 expected xfail; no stale baseline exclusion remains.
- Ruff lint and format checks pass for all four changed Python/test files.

## Production boundary

No production change is included in the local evidence above. The existing
workers continue running the prior image until the verified image-only rollout.
That rollout must preserve Machine IDs and image-excluded configuration, then
prove one certifier lease passes range 300 and reaches `job.succeeded`, followed
by fresh Quote/opportunity publications and a new accumulating qualification
epoch. M1 remains incomplete until that epoch reaches 86,400 continuous seconds
and its immutable certificate independently reverifies.
