# Plan 05.6-269 Summary: Deliver the Event Research Workbench

The M1 business dashboard now turns Structure, Quote Coverage, and Analysis rows
into one Event-level research path. The backend resolves `quote:current`, follows
that Quote generation's exact parent Structure generation, validates Event/group
ownership, and publishes compact detail and leg envelopes with explicit lineage.
The frontend strictly decodes those envelopes, highlights the originating view,
and keeps unavailable or unknown facts distinct from zero-result evidence.

Candidate economics now report the all-leg capital requirement, theoretical
gross profit, and gross ROI only when every required leg is executable. The UI
keeps fees, slippage, simultaneous execution, resolution, and settlement delay
under “not assessed”; it does not promote research evidence to a Certified
opportunity or trading authorization.

Focused Python/API/Postgres and Dashboard contract checks cover the contract
boundaries, and TypeScript typecheck plus production build pass. The scoped Fly
API deployment and smoke check passed without restarting the intentionally
stopped coordinator. Live detail and leg reads returned the same Quote/Structure
anchor. Browser checks against the production API covered links from all three
business views and a 375px layout; the Vercel production alias itself was Ready
but remained behind Vercel's login gate in the available browser sessions.

The broader combined regression command reached 57 passing tests before an
unrelated deployment-preflight test attempted to downgrade through the existing
production-forward-only revision 048. That baseline migration-policy failure is
outside this workbench plan and was not weakened or bypassed.

Final contract review also corrected nullable structural facts, group quality
field names, Unknown aggregate coverage, focus-neutral profit ranking, and
mobile identifier wrapping. The reviewer accepted the work for the agreed R&D
stage with one explicit deferral: the multi-query authority reuses exact
generation keys inside one read-only transaction, but does not yet request a
fixed REPEATABLE READ snapshot under concurrent rematerialization.
