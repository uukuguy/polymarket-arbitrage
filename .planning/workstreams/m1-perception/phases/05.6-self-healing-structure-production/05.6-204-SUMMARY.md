## Policy Matrix

- **Policy version:** `m1-rolling-qualification-v1`.
- **Contained reasons:** `recovery.retry`, `recovery.reclaim`,
  `recovery.process-replacement`, `recovery.circuit-probe`.
- **Breaking reasons:** `lease.expired`, `fence.mutated-stale`,
  `integrity.conflict`, `freshness.structure`, `freshness.quote`,
  `freshness.opportunity`, `evidence.gap`, `incident.p1-slo`,
  `progress.regressed`, `recovery.human-intervention`,
  `recovery.signature-budget`, `recovery.slo`, `identity.policy`,
  `identity.release`, `identity.config`, `identity.role`.
- **Non-breaking reasons:** `healthy`, `observation.healthy`, `progress`,
  `recovery.started`, `recovery.confirmed`.

Contained recovery stays inside an accumulating epoch only when duration,
SLO, resolution, and repeated-signature budget are proven. Breaking evidence
seals the current epoch as invalidated and opens a separate recovering boundary.

## Ingress and Recovery Observations

- Ingress is append-only in `m1_qualification_ingress_ledger`; every source row
  is identified by `(source, source_id, source_version)` and protected by a
  payload SHA-256 conflict check.
- The source cursor is `ingest_seq`, not `occurred_at`; this prevents late DB
  commits with older business timestamps from being skipped.
- Every tick inserts explicit freshness observations for Structure, Quote, and
  Opportunity before reading the ledger.
- Recovering epochs consume only `recovery.confirmed` into a new accumulating
  epoch. Other mapped facts are stored in `m1_qualification_recovery_observations`
  and surfaced in status as last recovery observation / last recovery breaker.

## Certificate Trust Boundary

- Application callers cannot supply certificate ID, identity key, counts, SLO,
  bounds, or evidence digest. Certificates are derived from a qualified
  `QualificationDecision`.
- Postgres derives certificate IDs from canonical payload digest and rejects
  direct UPDATE/DELETE on certificates and recovery observations.
- `read_qualification_certificate()` and `list_qualification_certificates()`
  run `SET TRANSACTION READ ONLY` and reverify payload, canonical bytes,
  certificate digest, epoch identity, bounds, and column consistency before
  returning data.

## CLI and Make Interface

- `make qualification-status` runs
  `uv run python -m polyarb.cli_control_plane qualification-status --json`.
- `make qualification-certificates limit=20` runs
  `uv run python -m polyarb.cli_control_plane qualification-certificates --limit "20" --json`.
- `make qualification-serve enable=1 interval_seconds=30` runs
  `uv run python -m polyarb.cli_control_plane qualification-serve --enable --interval-seconds "30" --json`.
- Without `enable=1`, `make qualification-serve` exits 2 before invoking the
  CLI. Status and certificates are strictly read-only and do not use `--enable`.
- The Make targets do not call Alembic, deployment, Fly/Machines APIs, R2,
  control-plane job mutation, quote/structure once commands, or pointer moves.
  `POLYARB_QUALIFICATION_DB_DSN` is handled only by the CLI.
