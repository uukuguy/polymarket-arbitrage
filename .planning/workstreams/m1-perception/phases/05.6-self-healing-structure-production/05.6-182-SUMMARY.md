# 05.6-182 — Bounded Postgres control-plane connection

## Root cause

`_control_plane_from_env()` created psycopg connections without a
`connect_timeout`. When the separately designated production authority is
unreachable, a preflight or worker turn could block on TCP/DNS longer than the
control-plane recovery budget, producing no typed deployment result.

## Change

- Every Postgres connection made by the control-plane CLI now supplies
  `connect_timeout=5`.
- This complements the bounded R2 connection/read configuration from
  05.6-181. It does not alter lease, retry, pointer, or schema semantics.

## Verification

- A new CLI connection-factory contract test failed first because no kwargs
  were passed to `psycopg.connect`, then passed with the five-second budget.
- `uv run pytest tests/m1-perception/test_control_plane_cli.py tests/m1-perception/test_r2_sync.py -q` — passed.
- Changed-file Ruff and Python compile passed.

## Follow-up

Run the read-only production preflight again. Its outcome is now bounded and
must be recorded before any additive schema migration or production worker
creation.
