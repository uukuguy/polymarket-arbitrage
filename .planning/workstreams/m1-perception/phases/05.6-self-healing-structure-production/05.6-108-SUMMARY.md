# 05.6-108 Summary — Render a named, non-deploying rollout contract

## Delivered

- Added a pure-local rollout renderer and
  `make control-plane-render-rollout enable=1 api_app=... worker_app=...
  expected_database=... output_dir=...`.
- It renders the two isolated Fly app configs and a machine-readable ordered
  checklist: preflight, revision-009 migration, shadow parity, fault/soak, and
  separately authorized reversible switch.
- It rejects `polyarb-l1`, duplicate/invalid app names, blank database names,
  unresolved templates and pre-existing output artifacts. It makes no
  Postgres, R2, Fly, HTTP, secret, migration or pointer call.

## Verification

- Renderer contracts prove exact output, staged checklist and legacy-app
  refusal.
- CLI contract proves local rendering never constructs a control-plane client.
- A temporary-directory Make invocation generated all three expected files.
- Full transactional regression, Ruff and planning gate run before commit.

## Boundary

- Rendering is preparation, not authorization. Generated files retain named
  target identity but must be reviewed and executed only after a designated
  cloud environment is confirmed.
