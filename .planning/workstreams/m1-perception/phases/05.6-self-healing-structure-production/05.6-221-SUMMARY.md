# 05.6-221 Summary — Fail fast on stale climb test selectors

## Outcome

- A climb gate can no longer carry a renamed explicit pytest node ID until a
  later autonomous cycle. One collect-only contract validates every `::`
  selector across every gate profile against the repository's live test graph.
- The first red run found nine stale selectors, including the H-037 restart
  failure and qualification v1→v2 semantic renames. Each now targets its
  current equivalent test.
- Resuming H-037 also exposed and repaired a contradictory state assertion:
  active in-flight work now outranks the empty-pending fallback when validating
  `next_action`.
- H-037 cycle 40 remains append-only as an 80-point falsified orchestration run;
  the repaired exact HEAD must create a separate confirming run.

## Root cause

- `eval_local.py` and its expected-command test duplicated the same strings.
  Their agreement proved only that both copies matched, not that pytest could
  collect the named tests.
- The defect surfaced late because integration runs whole files while restart
  runs exact selectors. A renamed test therefore passed normal regression but
  failed the final focused gate.

## Verification

- The new collect-only contract failed on all nine old selectors before the
  implementation change and passes after their semantic mapping.
- All 46 climb eval/adapter/cycle tests, Ruff and diff checks pass.
- A fresh H-037 climb cycle is required after this commit.

## Boundary

- No timeout, retry count or production authority changed. This repair affects
  local validation orchestration only.
