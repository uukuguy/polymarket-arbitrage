## What Shipped Locally

- Revision 026 creates or validates `m1_runtime_controller_capability` and
  `m1_qualification_worker_capability` as non-login, non-inheriting,
  non-elevated PostgreSQL roles.
- Runtime controller authority is bounded to runtime/job reads plus controller
  lease and observe-decision writes. It has no recovery-action mutation grant,
  no qualification function execution, and no public sequence privileges.
- Qualification worker authority is bounded to qualification/publication reads,
  source cursor/epoch/recovery-observation writes, and two reviewed functions.
  It cannot directly insert the ingress ledger or use the ledger identity
  sequence.
- Hardened `SECURITY DEFINER` functions set `search_path = pg_catalog`, use
  schema-qualified `public.*` application objects, and revoke ambient EXECUTE
  from PUBLIC, Supabase fixture roles, and the new capability roles where
  appropriate.
- Every runtime-controller and qualification-worker application relation and
  routine reference is schema-qualified. Daemon startup checks enumerate every
  non-system schema, relation, sequence and SECURITY DEFINER routine, including
  ownership/effective privileges, database CREATE, unsafe active/role/database
  search-path settings, and exact PostgreSQL 16 membership option tuples.
  Direct, PUBLIC, inherited and namespace amplification therefore fails closed
  before runtime reconcile or qualification service construction.
- Operator tooling can preflight, provision/rotate, verify, and disable the two
  login roles through Make targets. Mutation commands require `enable=1`, check
  database and revision 026, use independent password env vars, and avoid
  printing SQL, DSNs, passwords, auth values, or provider bodies.
- Admin-only preflight/provision/disable consumes
  `POLYARB_CONTROL_PLANE_DB_ADMIN_DSN`; the two scoped verification/app paths
  retain their own canonical DSNs. The runbook explicitly returns to the admin
  credential for emergency disable, and no app receives the admin or peer-app
  credential.
- Rollout rendering binds final release/config identity into local-only
  artifact version 10 with two new private apps, revision 026, observe-only
  mode, and an empty recovery allowlist unless explicit targets are supplied.
- Runtime-controller consumes only `POLYARB_SUPABASE_DB_DSN`; qualification
  consumes only `POLYARB_QUALIFICATION_DB_DSN`. CLI readers, admin verify,
  templates/processes, contract tests, and runbook agree, with no aliases
  installed into Fly.
- Both daemon readers reject DSN `options`/`search_path` overrides before
  connection or mutation and connect with controlled `pg_catalog,public`
  resolution. Database `TEMPORARY` remains explicitly allowed for original-app
  compatibility; database CREATE and every unreviewed namespace capability are
  denied.
- Migration downgrade restores revision-024 ACL, `prosecdef`, and `proconfig`
  posture for every function changed by 026. Qualification generic failures
  emit bounded stable reason codes and do not echo exception text.
- `runtime-observe-only.json` is an explicitly required evidence path and names
  canonical reviewed template paths and SHA256s. `make planning-status` fails
  on missing/invalid JSON, malformed/non-object implementation data, or a
  missing/empty/ill-typed reviewed-artifact list before recomputing every hash.
- `.githooks/pre-commit` remains the staged/manual SUMMARY safety layer;
  `.githooks/commit-msg` enforces plan-scoped subjects using Git's real
  message-file argument and fails closed when repeated numeric phases cannot be
  resolved from one unambiguous staged workstream path.
