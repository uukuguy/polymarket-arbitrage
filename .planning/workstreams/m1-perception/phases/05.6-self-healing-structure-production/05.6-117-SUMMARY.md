# 05.6-117 Summary — Continuously admit non-overlapping source windows

## Delivered

- Added a Postgres advisory-transaction-lock cadence admitter before all
  source-page work.
- A deterministic 300-second time bucket is the durable source-window identity.
  Repeated ticks/restarts cannot add a second window for the same bucket.
- Any `running` or `events-complete` traversal blocks later buckets, preventing
  overlapping Gamma traversals across replaceable worker machines.
- The long-running scheduler now owns this continuous admission turn; the
  explicit named source-window command remains available for operator drills.

## Verification

- Real PostgreSQL verifies same-bucket idempotency and later-bucket exclusion
  while a traversal is active.
- Scheduler rotation and source-admitter contracts pass, together with Ruff,
  manual validation, and the source-worker regression suite.

## Boundary

The loop is ready to run but has not been deployed to a designated cloud
environment. Its cadence is conservative (300 seconds) until real shadow and
soak evidence establishes an operational rate.
