# Plan 05.6-35 Summary: Bound stale Quote hydration retries

- Production logs proved that the isolated parent retried an already stale
  durable Quote feed every 15 seconds. Each retry emitted only a log line,
  while Structure was concurrently deferring on SQLite writer contention.
- The hydrator now records its failure type/count/timestamp in the existing
  Quote runtime and waits at least one Quote cadence (60 seconds) after a
  `StaleQuoteRunError`. It does not turn stale data into a feed or clear the
  existing Quote P1; a newly certified feed resets the evidence atomically.
- `/perception/producer-progress` and the Fly incident console now show the
  parent-side hydration evidence beside the durable Quote attempt. Operators
  can distinguish a collection failure from a stale-read retry without SSH.
- Focused RED/GREEN retry, runtime recovery, and Dashboard projection tests
  plus changed-file Ruff passed. Production deployment/natural recovery remains
  required before any stability claim.
