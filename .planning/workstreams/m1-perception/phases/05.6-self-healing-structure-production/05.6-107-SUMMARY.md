# 05.6-107 Summary — Split the durable control-plane read service

## Delivered

- Added `polyarb.control_plane.api`, an independent HTTP service containing
  only `/healthz` and `/perception/control-plane`. It carries no SQLite,
  scheduler, R2, or data-worker dependency; readiness is 503 when the durable
  Postgres authority cannot be read.
- Added `make control-plane-api-serve enable=1` for explicit local/service
  invocation.
- Added separately rendered Fly templates for a Postgres-read-only API app and
  a fenced scheduler worker app. Neither has a volume; only the worker app
  receives R2/writer credentials and only the API app has public HTTP health.

## Verification

- HTTP contracts prove an independent successful read and typed unavailable
  readiness behavior.
- Static TOML contracts prove process, HTTP and no-volume/no-secret-sharing
  topology.
- Full transactional regression, Ruff, Make dry-run and planning gate run
  before commit.

## Boundary

- Templates contain deliberate app-name placeholders and are not deployment
  configs. No Fly app, secret, machine, network route, database migration or
  pointer has been changed.
