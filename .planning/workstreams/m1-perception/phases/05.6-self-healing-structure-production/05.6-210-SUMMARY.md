# Plan 05.6-210 Summary: Failure Identity and Resumable Interruption

Production recorded five attempts for one source job as Timeout, ValueError,
Timeout, Timeout, ValueError. The old circuit counted every failure on the job
as the same consecutive defect and opened at five. This was a state-model bug,
not evidence that a timeout needed to be enlarged.

Revision 033 stores the active failure fingerprint on each circuit. Workers
derive a SHA-256 identity from component, exception type and innermost code
site, never from exception text. Equal identities increment; a changed identity
starts a new streak at one and closes the false circuit. Attempts and operator
snapshots expose only the bounded fingerprint and coarse failure signature.

Gamma 2xx responses with malformed JSON now raise a typed,
`GammaMalformedResponseError` containing bounded status/content-type/byte-count
metadata and no response body. Structure materialization also stopped writing
raw exception messages into incidents.

The reverse interruption audit found that a normal service stop used the same
defect retry transaction and could itself open a circuit after three deploys.
`finish_interrupted()` now atomically appends service-stop runtime evidence,
closes the attempt and makes the job immediately retryable. It preserves the
preceding real defect streak but neither increments nor clears it, and creates
no new incident. Ordinary defect retry rejects `service.interrupted` so future
callers cannot silently mix the models again.
