# Plan 05.6-262 Summary: Serialize Structure and Quote Admission

Structure certification now takes the same transaction advisory lock as recurring Quote
admission before it publishes a manifest or creates the immediate Quote successor. Quote refresh
also treats a ready, retrying, leased or checkpointed Structure certifier as a handoff in
progress; the long-lived initial `waiting` certifier does not suppress cadence refresh while
Structure normalization is still underway.

The reverse ordering is explicit too. If an older Quote or Opportunity successor already owns
the executable chain, Structure certification raises `StructureSuccessorBusyError`, an
`IncompleteStructureGenerationError` subtype. The existing worker therefore returns the job to
ordinary `waiting` without an incident, and durable receipts allow its normal certifier repair
path to make it runnable later.

Real PostgreSQL regressions prove both orderings: a leased Structure certifier makes refresh
return `busy` and only the new Structure's initial Quote admission remains active; an already
active Quote successor prevents Structure terminal mutation and leaves its certifier lease
unchanged. Pointer-conflict commissioning now scopes its intentional overlap by temporarily
suspending already-staged successor states and restoring them after the competing candidate is
prepared.
