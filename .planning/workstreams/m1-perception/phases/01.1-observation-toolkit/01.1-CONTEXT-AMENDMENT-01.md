## 修正后的 T1 设计

### Schema 变更（取代 amendment 前的 markets +category/tags）

**markets 表**：
- ❌ 删除：`category TEXT`、`tags TEXT`（列在 SESSION 13 commit 1fdf670 加上但**字段实际无数据**）
- ✅ 新增：`event_id TEXT REFERENCES events(id)` — market 归属哪个 event 的外键

**新表 1：events**
```sql
CREATE TABLE events (
  id              TEXT PRIMARY KEY,
  slug            TEXT NOT NULL,
  title           TEXT,
  ticker          TEXT,
  active          INTEGER NOT NULL DEFAULT 1,
  closed          INTEGER NOT NULL DEFAULT 0,
  liquidity_usd   REAL,        -- event-level aggregate
  volume_usd      REAL,
  end_time_ms     INTEGER,
  fetched_at_ms   INTEGER NOT NULL,
  snapshot_id     INTEGER NOT NULL REFERENCES snapshots(id)
);
CREATE INDEX idx_events_slug ON events(slug);
CREATE INDEX idx_events_snapshot ON events(snapshot_id);
```

**新表 2：event_tags**（多对多）
```sql
CREATE TABLE event_tags (
  event_id    TEXT NOT NULL REFERENCES events(id),
  tag_id      TEXT NOT NULL,           -- Polymarket 的 tag ID（不变）
  tag_label   TEXT NOT NULL,           -- 人类可读 "Finance" / "Crypto"
  tag_slug    TEXT NOT NULL,           -- URL slug "finance" / "crypto"
  snapshot_id INTEGER NOT NULL REFERENCES snapshots(id),
  PRIMARY KEY (event_id, tag_id, snapshot_id)
);
CREATE INDEX idx_event_tags_label ON event_tags(tag_label);
CREATE INDEX idx_event_tags_slug ON event_tags(tag_slug);
```

### 抓取流程（gamma_client.py）

新增 `fetch_all_active_events() -> list[dict]`：
- pagination 跟 `/markets` 同模式（page_limit=100, offset 翻）
- 返回 raw events 列表（含 nested tags + nested markets）
- normalizer 拆 events → events row + event_tags rows + market→event_id 反查映射

**调度**：在 snapshot orchestrator 里**新增 phase 0/8**（events fetch），**早于** 现有 Phase 1（markets fetch）。Banner 8/8 改 9/9（plan 02 已经把 7/7→8/8，这次再 +1 到 9/9）。

> **替代设计 — 不重构 phase 数**：events fetch 跟 markets fetch 并行（asyncio.gather），不算独立 phase。
> 但跟 Phase 1 保持 phase 编号风格一致更重要（每个 phase 是 sequential checkpoint），所以保留新增 phase。
