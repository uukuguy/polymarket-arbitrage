`compare_snapshots` 的 SQL 关键结构：

```sql
WITH a AS (SELECT *, NULL::VARCHAR AS category, slug AS _slug FROM read_parquet(?)),
     b AS (SELECT *, NULL::VARCHAR AS category, slug AS _slug FROM read_parquet(?))
SELECT
    COALESCE(a.slug, b.slug)        AS slug,
    COALESCE(a.question, b.question) AS question,
    NULLIF(COALESCE(NULLIF(NULLIF(a.category, ''), 'None'),
                    NULLIF(NULLIF(b.category, ''), 'None')), '') AS category,
    a.mid_price AS mid_from, b.mid_price AS mid_to,
    (b.mid_price - a.mid_price) AS mid_drift,
    a.liquidity_usd AS liq_from, b.liquidity_usd AS liq_to,
    (b.liquidity_usd - a.liquidity_usd) AS liq_drift,
    CASE
        WHEN a._slug IS NULL THEN 'appeared'
        WHEN b._slug IS NULL THEN 'vanished'
        ELSE 'persistent'
    END AS state
FROM a FULL OUTER JOIN b USING (_slug)
ORDER BY
    CASE WHEN a.mid_price IS NULL OR b.mid_price IS NULL THEN 1 ELSE 0 END,
    ABS(COALESCE(b.mid_price, a.mid_price) - COALESCE(a.mid_price, b.mid_price)) DESC
```

> 实现层比 PLAN 骨架精细化的两点：
> 1. 用 `_slug` 别名 + `USING (_slug)`，避免 DuckDB FULL OUTER JOIN 在 SELECT 中
>    引用 `a.slug` / `b.slug` 时 USING 列消歧的 corner case
> 2. ORDER BY 用 `CASE WHEN NULL` 把单边行排到末尾，再按 ABS drift 降序 — 单纯
>    `ABS(diff) DESC` 在 NULL 上排序不稳定

```python
def track_market(slug: str, parquet_root: Path) -> pd.DataFrame:
    glob = str(parquet_root / "**" / "*.parquet")
    parquet_files = list(parquet_root.rglob("*.parquet"))
    if len(parquet_files) > _PARQUET_COUNT_WARN_THRESHOLD:  # 200
        warnings.warn(...)
    con = duckdb.connect()  # in-memory
    try:
        return con.execute(
            """
            SELECT
                snapshot_taken_at_ms AS taken_at_ms,
                snapshot_id, slug, question, category,
                mid_price, best_bid_price, best_ask_price,
                (best_ask_price - best_bid_price) AS spread,
                liquidity_usd, volume_usd
            FROM read_parquet(?, union_by_name=true)
            WHERE slug = ?
            ORDER BY taken_at_ms, snapshot_id
            """,
            [glob, slug],   # 参数化（防 T-01.1-16）
        ).fetchdf()
    finally:
        con.close()
```

- WHERE on slug 经 parquet zonemap 下推（RESEARCH §3.1）
- `[glob, slug]` 列表参数化，永不字符串拼

```python
@app.command(name="compare-snapshots")
def compare_snapshots_cmd(from_id, to_id, limit=50, verbose=False):
    if from_id is None or to_id is None:
        from_id, to_id = latest_snapshot_pair(settings.db_path)
    from_path = resolve_snapshot_path(from_id, settings.db_path)
    to_path   = resolve_snapshot_path(to_id, settings.db_path)
    df = compare_snapshots(from_path, to_path).head(limit)
    render_table(df, title=f"compare snapshots {from_id} → {to_id}",
                 columns=("slug","category","state","mid_from","mid_to",
                          "mid_drift","liq_from","liq_to"))

@app.command(name="track-market")
def track_market_cmd(slug, verbose=False):
    df = track_market(slug, settings.parquet_root)
    if df.empty: raise typer.Exit(1)
    render_table(df, title=f"track-market: {slug}",
                 columns=("taken_at_ms","snapshot_id","mid_price","best_bid_price",
                          "best_ask_price","spread","liquidity_usd","volume_usd"))
```

## Deviations from Plan

### Plan refinements applied during execution（非 deviation，是骨架增强）

**1. ORDER BY NULL-safety（PLAN 未要求）**

- PLAN 骨架：`ORDER BY ABS(COALESCE(b.mid_price, 0) - COALESCE(a.mid_price, 0)) DESC`
- 实际实现：`ORDER BY CASE WHEN NULL THEN 1 ELSE 0, ABS(COALESCE(...)) DESC`
- 原因：PLAN 骨架的 `COALESCE(x, 0)` 在 appeared/vanished 行会让 mid_drift 看起来
  比真实漂移更大（`b.mid_price - 0` 与 `0 - a.mid_price`），把无意义的 0 比较
  混进 top 排序。改为先用 CASE 把单边 NULL 行排末尾，再排 ABS — 顶部永远是真
  drift。

**2. `latest_snapshot_pair` 加 `WHERE market_count > 0`（PLAN 未要求）**

- PLAN 骨架：`SELECT id FROM snapshots ORDER BY id DESC LIMIT 2`
- 实际实现：`SELECT id FROM snapshots WHERE market_count > 0 ORDER BY id DESC LIMIT 2`
- 原因：m1 实盘曾出现 snapshot 因 Gamma 抓取中断写入 0 行（market_count=0）。默认
  对里混进空 snapshot 会让 `make compare-snapshots` 显示全部市场都 vanished。
  这是 plan 04 跑实盘前 plan 01 的已知 known-orange 的二阶后果。

**3. `warnings.warn` 而非 `logger.warning`（PLAN 写的是 `logger.warning`）**

- 原因：让单测可以用 `pytest.warns(...)` 直接断言（标准 idiom），而 `caplog`
  捕获 loguru 在 pytest 下需要额外 propagate 配置。功能等价。
