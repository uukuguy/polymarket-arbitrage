## Decisions Made

1. **Task 3 不强行执行原计划的"5 题 Q&A"**
   原 PLAN.md `<task type="checkpoint:human-verify" gate="blocking">` 设计是 Claude 提 5 题 → 用户答 → Claude 写 VERIFICATION.md → 决定下一步。但 2026-05-10 用户实际走端到端时给出的洞察（"全量快照是跨越下载时长的模糊影像，应该只能参考作用，并非主角；定向快照应是生产级工作流，单市场又一套设计，然后 K 线"）远超 5 题 Q&A 边界。**正确处理**：升格为 architecture thread，由 extract_learnings 01.1 + Phase 02 discuss-phase 消化，而不是塞回 5 题问答里。

2. **教学文档 4 个设计取舍 ≠ PLAN.md 列的 3 个**
   PLAN 列出 3 个（翻译缓存表 / SQL 防御 / AST walker）；实际写时拆出 DuckDB `union_by_name=true` 与 schema 演进不变量为独立第 4 节，因为它直接对应自检题 Q5（如何修改列类型），把"不变量在哪个文件"写明便于回溯。

3. **教学文档 5 题答案完整写在正文**
   不只是题面 + "见自检题 PR"。CLAUDE.md 教学文档纪律强调"30 秒心智模型 + 解释 + 自检"，把答案放在正文让用户可以"先答再对照"，FAQ 增量区单独处理后续真问答。

4. **本 SUMMARY 补写而非直接进入 Phase 02**
   Process gap 不能让它累积。retroactive 补写代价 ~30 分钟，价值是后续 extract_learnings 01.1 / Phase 02 discuss 都需要 plan 06 的状态闭环作为前置。
