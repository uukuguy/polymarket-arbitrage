# Phase 05.1 Learnings: durable-l2-data-chain-recovery

## Decisions

### D-01 NOTIFY is a wake hint; the cursor ledger owns completeness

The listener records connection/notification truth and wakes one serialized
reconciliation pump. Polling reads durable latest/cursor state independently,
and the cursor advances only after candidate, WS, and mirror convergence all
succeed.

### D-02 Candidate history uses composite identity; WS uses asset identity

Supabase candidate rows reconcile by `(asset_id, recipe_name)`, while the live
socket subscribes to the unique asset union. Conflating these sets either loses
recipe history or duplicates wire membership.

### D-03 Quiet refresh requires a real membership edge and business evidence

Repeated subscribe was insufficient. The final design serializes
unsubscribe→subscribe with `initial_dump=true`, then waits for a same-generation
book event whose normal mirror dispatch succeeds. Send success mutates no
freshness clock.

### D-04 Empty live market projections are invalid input

A zero-row `markets_latest` response contradicting a valid nonzero snapshot is
projection failure, not desired state. L1 rejects empty replacements before any
remote mutation; L2 freezes last-known-good state and cursor for retry.

### D-05 Test environments default all external adapters off

Because Settings automatically reads `.env`, mocking only the market clients is
not sufficient. Repository-wide autouse defaults clear write-capable cloud and
alert credentials; tests opt in explicitly with local/dummy values.

### D-06 Phase 05.1 and L3 N=5 remain separate gates

Phase 05.1 closes the durable L2 chain. L3 `0/10` is still a real blocker owned
by Phase 05 Plan 06 and cannot be converted to success by weakening thresholds.

## Lessons

### A green full test suite can still be a production writer

The earlier suite inherited Supabase/R2 credentials and modified production
while all mocks and assertions passed. Test correctness includes side-effect
containment, not only assertion outcomes. Production write counters before and
after the suite are now part of the evidence.

### Non-transactional replacement APIs need input validity at the outer edge

PostgREST DELETE→INSERT cannot be made safe by handling insert failure after the
delete. The guard must run before snapshot upsert or table deletion. This pattern
applies to caches, search indexes, and any remote replace operation.

### A historical mechanism PASS does not override current health

The first quiet-refresh proof was genuine, but a later strict probe found the
empty projection. Preserving both facts avoided two opposite errors: discarding
valid mechanism evidence and falsely declaring current readiness.

### Freshness clocks identify different links

WS frame age can be seconds while TOB mirror age is hours. Transport frames,
valid book projection, remote mirror success, and candidate fetch each need their
own anchor; one coarse heartbeat cannot represent the chain.

### Boundary checks must extend past the nearest failure threshold

The re-acceptance window ended with mirror age at 565.4 seconds against a
600-second fail threshold. A follow-up check proved a real mirror write at the
boundary and reset the age to 61.7 seconds, eliminating a near-edge false pass.

### Exact instance identity turns time-separated evidence into one chain

Machine ID alone is insufficient because a process may restart on the same
machine. Machine, instance, creation/start anchor, image tag, and digest were
matched before and after production windows.

## Patterns

### Wake-hint plus durable-ledger consumer

Use a lossy low-latency notification only to wake a consumer; poll a durable
position and commit after idempotent convergence.

### Success-only cursor commit

Return explicit success from every required projection. Any false/exception
keeps the cursor behind so the next wake retries the entire desired state.

### Same-generation business-evidence waiter

For control operations that request data, bind the waiter to connection
generation and resolve it only from the normal data/mirror path.

### Invalid-empty projection guard

When the source domain cannot legitimately be empty, treat `HTTP 200 + []` as
an integrity failure. Preserve last-known-good state and retry; never collapse a
live desired set.

### External-adapter opt-in tests

Global test defaults disable network writers and alert sinks. A test that needs
one adapter must provide explicit local/dummy configuration at the call site.

## Surprises

### The destructive writer was pytest, not either Fly service

Fly logs had the successful L1 projection but no final DELETE. Database trigger,
cron, and cascade checks were clean. The missing writer existed in the local test
process because `.env` was loaded implicitly.

### The deployed old process recovered without a deploy

Once snapshot 574 repopulated 1942 rows, the unchanged L2 instance fetched them,
restored three candidates, caught the cursor up, and returned to strict HTTP 200.

### Active WS traffic can coexist with a near-stale mirror

During re-acceptance, WS age remained under 11 seconds while mirror age climbed
past 565 seconds. Only a later real TOB event refreshed the mirror anchor.

### Testcontainer failures were test drift, not migration defects

Alembic 003/004 tests targeted `head` and assumed Supabase's `anon` role existed
in vanilla Postgres. Seeding the platform role and testing each revision restored
the intended contract without changing migrations.
