# Phase 05.1 Plan 01: Durable Listener and Reconciliation Pump Summary

**Termination-aware LISTEN plus one serialized NOTIFY/timer pump that advances the durable cursor only after awaited candidate refresh success**

## Performance

- **Duration:** 8 min
- **Started:** 2026-07-18T00:29:30Z
- **Completed:** 2026-07-18T00:37:06Z
- **Tasks:** 3
- **Files modified:** 8

## Accomplishments

- A real asyncpg termination listener now clears connection truth and drives a
  bounded reconnect loop without restarting L2.
- NOTIFY storms and the 60-second durable poll converge through one sequential
  reconciliation owner; timer catch-up remains active while LISTEN is down.
- Candidate cursor writes occur only after awaited refresh success and mutate
  `updated_at`; refresh/write failures retain the old retryable cursor.
- Removed per-snapshot task fan-out, premature startup cursor commits, and the
  synthetic `snapshot_id=-1` startup prime from `l2_main`.

## Decisions Made

- Kept listener and reconciliation as independent tasks so loss of the optional
  low-latency doorbell cannot stop durable polling.
- Coalesced to the newest snapshot rather than replaying intermediate IDs because
  the business computation reads the current `markets_latest` projection.
