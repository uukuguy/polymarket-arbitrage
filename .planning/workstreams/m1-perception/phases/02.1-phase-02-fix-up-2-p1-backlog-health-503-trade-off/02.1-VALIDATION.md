---

## Sampling Rate

- **After every task commit:** Run `uv run pytest tests/m1-perception/test_<changed>.py -xvs` (per-file targeted)
- **After every plan wave:** Run `uv run pytest tests/m1-perception/ -x` (full suite, abort on first failure)
- **Before `$gsd-verify-work`:** Full suite must be green (3 pre-existing failures are deferred — see deferred-items.md)
- **Max feedback latency:** ~30 seconds full suite

**Threat refs**:
- T-02.1-01: HMAC bypass on /control/unpause — anyone with /control/unpause path can manipulate daemon state if HMAC not enforced
- T-02.1-02: Missing X-Signature header should 401 (constant-time compare, no timing oracle)

**Notes**:
- 02.1-01-02 (chaos Inj 3) is **prod-grade verification per Phase 02 L7** — manual chaos via Plan 01 Task 3 `checkpoint:human-verify`. Not a Makefile target — PATTERNS.md confirms chaos steps are manual `flyctl` commands, not a `make chaos-inj-3` target
- 02.1-03-04 (Fly checks list) is **post-deploy smoke** — fly.toml change requires deploy to actually exercise; covered by Plan 03 Task 5 `checkpoint:human-verify`
- 02.1-02-01 ties to a **new test case** (`test_unpause_with_empty_body_matches_makefile_target`) that sends `content=b""` rather than `make_signed_request({})`. This makes the unit test exercise the exact bytes that `make unpause-prod` sends in production (HMAC of `b""`, not `b"{}"`). The remaining HMAC-enforcement unit tests (missing/invalid HMAC, already-running idempotency, transitions) continue to use `make_signed_request({})` because their assertions do not depend on the exact body shape — only the prod-path success test needs the empty-body fixture
