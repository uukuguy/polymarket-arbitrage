## Decisions Made

- **D-05 (recap):** Two-endpoint split — option (c) chosen over (a) "degrade /health to always 200" (would break Better Stack alarm semantics) and (b) "Fly TCP probe" (doesn't validate HTTP service is actually healthy)
- **D-06 (recap):** `/healthz` body is full-mirror of `/health` body, not a simplified shape. Rationale: future check additions auto-flow to both endpoints; eliminates the temptation to diverge logic
- **/healthz public per D-22 amendment:** No HMAC. Trust boundary identical to /health; no IP/secret/PII exposure
- **Helper boundary chosen:** `_build_health_checks` returns `(checks, overall)` — overall lives in the tuple, not the body. The handler decides what HTTP code to map from `overall`. Body construction (`_build_health_body`) is a separate helper to keep handlers thin
