# Phase 02.1 Plan 02: /control/unpause Endpoint (BUG-8) Summary

**Daemon now exposes a HMAC-signed `POST /control/unpause` endpoint plus a `make unpause-prod` Makefile target — prod ops can return a PAUSED daemon to RUNNING in a single command instead of the previous SSH + sqlite3 UPDATE + restart procedure. The underlying `SnapshotScheduler.unpause()` method (`scheduler.py:192`, 0 callers per codegraph) is finally wired through HTTP.**

## Key Code Changes

- **`src/polyarb/http/control.py`** (NEW, ~180 lines including module docstring): `control_auth_middleware` async function (path guard `startswith("/control")`, HMAC-SHA256 of body, `hmac.compare_digest` constant-time), `ControlAuthMiddleware(BaseHTTPMiddleware)` class wrapper, `unpause` handler (PAUSED → call `scheduler.unpause()` sync → 200 with state/counter; already RUNNING → 200 `already_running`), `pause` + `control_status` 501 stubs.
- **`src/polyarb/http/app.py`**: imports the 4 control symbols, appends `Middleware(ControlAuthMiddleware, secret=secret)` to the middleware list, registers 3 new `/control/*` routes.
- **`Makefile`**: `unpause-prod` target — `printf '' | openssl dgst -sha256 -hmac "$$SECRET"` builds the empty-body HMAC and `curl` POSTs it to `https://polyarb-l1.fly.dev/control/unpause` with `Content-Length: 0`.
- **`tests/m1-perception/test_control_unpause.py`** (NEW, 5 tests, ~150 lines): covers PAUSED→RUNNING, already-RUNNING idempotent, missing HMAC 401, invalid HMAC 401, and the ISSUE-04 empty-body sentinel that proves the exact bytes `make unpause-prod` sends are HMAC-valid against the daemon.

## Decisions Made

- **D-03 confirmed at execution**: HMAC verification logic is inlined into `control_auth_middleware` (not imported from `scan.py`) — RESEARCH Area 3 recommendation B. This keeps scheduler-state-machine ownership distinct from scanner-trigger ownership for future evolution.
- **D-04 contract**: `unpause` response carries `failure_counter: 0` so ops can verify the counter actually cleared (T-02.1-8-05 — counter visible inside HMAC-protected channel is acceptable debug context, not info disclosure).
- **MagicMock side_effect pattern** for the test scheduler: conftest's `http_test_client` builds a `MagicMock()` scheduler, so `scheduler.unpause()` is a no-op by default. Tests install a `side_effect` that mutates `scheduler.state` and `_failure_counter`, mirroring the real `SnapshotScheduler.unpause()` body — this lets unit tests verify the handler-to-method wiring without spinning up a real scheduler + SQLite store.
