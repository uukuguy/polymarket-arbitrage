## Decisions Made

- **Audit-log message wording:** Used both "mirror disabled" AND "reason=config-disabled" so the test grep matches either phrase and ops can grep on either substring in Fly logs.
- **Breadcrumb data shape:** `{"supabase_mirror_enabled": False, "snapshot_id": snapshot_id}` — the boolean self-documents the disabled state for anyone reading the Sentry trail, the snapshot_id ties the breadcrumb to a specific snapshot row in SQLite/Supabase.
- **Test sink mechanism:** pytest `caplog` does not see loguru messages because loguru does not propagate to stdlib's logging hierarchy. Tests use a loguru `logger.add(StringIO())` sink, captured + asserted on `getvalue()`. This pattern is reusable for any other loguru-message assertion.
- **Settings construction in tests:** dev `.env` on this machine has live Supabase + R2 credentials, which would (a) auto-enable `supabase_mirror_enabled` (defeating the test) and (b) trigger a real R2 upload (network call). `_make_settings` explicitly passes empty `supabase_url`, `supabase_service_key`, `r2_endpoint`, `r2_access_key_id`, `r2_secret_access_key` to force both fail-soft paths to skip. This is purely test isolation, not production behavior.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test capture mechanism: caplog → loguru sink**
- **Found during:** Task 2 GREEN (running tests after orchestrator change)
- **Issue:** The plan's PATTERNS.md test template used `caplog.at_level(logging.INFO, logger="polyarb")` but pytest's `caplog` fixture captures stdlib `logging` records; the project's `polyarb.snapshot.orchestrator` uses `loguru.logger.info(...)`. Loguru does not propagate to stdlib by default, so `caplog.records` was empty even after the orchestrator change correctly emitted the log line (verified in pytest live capture: the log appeared in test stdout but not in `caplog`).
- **Fix:** Test 1 (`test_mirror_disabled_logs_audit_entry`) now adds a loguru `StringIO` sink before invoking `run_snapshot`, captures the buffer's `getvalue()`, and asserts the substring is present. The sink is removed in a `finally` block to keep the global loguru config clean across tests.
- **Files modified:** `tests/m1-perception/test_orchestrator_mirror_skip.py`
- **Verification:** `uv run pytest tests/m1-perception/test_orchestrator_mirror_skip.py` → 2 passed.
- **Committed in:** Task 2 commit (rolled into the GREEN feat commit so the test pinning + the production code that satisfies it land together).

**2. [Rule 3 - Blocking] Explicit empty credentials in `_make_settings`**
- **Found during:** Task 1 RED (first pytest run)
- **Issue:** `Settings(...)` loaded `.env` from the project root (default `model_config.env_file=".env"`), so the dev machine's real Supabase + R2 keys auto-enabled `supabase_mirror_enabled=True` — defeating the test precondition. First pytest run failed with `AssertionError: test precondition: mirror must be disabled` (which is a useful guard but means the test can't run on a credentialed dev box without explicit isolation).
- **Fix:** `_make_settings` now passes `supabase_url=""`, `supabase_service_key=SecretStr("")`, `r2_endpoint=""`, `r2_access_key_id=SecretStr("")`, `r2_secret_access_key=SecretStr("")` in the constructor — overriding whatever `.env` provides for the duration of the test.
- **Files modified:** `tests/m1-perception/test_orchestrator_mirror_skip.py`
- **Verification:** Pre-condition assert (`settings.supabase_mirror_enabled is False`) now passes on the dev machine.
- **Committed in:** Task 1 commit (test file) — present in the initial RED commit, surfaced because Task 1's pytest revealed the issue.
