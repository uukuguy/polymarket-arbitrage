quoted connection string to Node's URL parser. Its exception included the raw
input in tool output, so the production owner password must be treated as
compromised.

Containment completed:

- Migration did not run; production remained revision `006`.
- A read-only direct TLS query confirmed the intended project/database/user and
  revision before containment.
- SQL password rotation was attempted and rejected by Supabase with
  `permission denied to alter role`; no password changed.
- The compromised owner DSN was removed from local `.env`.
- The unused generated replacement was removed from Keychain.
- Browser automation, Supabase CLI login state, and a Management API token were
  unavailable, so Dashboard rotation could not be completed automatically.

Recovery completed before migration: the exact project password was rotated
through Supabase Dashboard, the replacement was stored only in macOS Keychain,
direct TLS was re-proved, and production was migrated exactly once to 007. The
owner DSN was not restored to `.env` or Fly.

### Recovery completed

At `2026-07-24T04:04Z`, the existing Edge/GitHub session reached the exact
Supabase project and reset the database password. Supabase's generated
authoritative direct connection value was transferred directly into macOS
Keychain without printing it; the clipboard was cleared immediately. A direct
TLS login as `postgres` succeeded before any migration.

The compromised credential is no longer active. No owner DSN was restored to
`.env`, and the owner credential is not present in the Fly secret inventory.
The migration then followed the recorded 006 proof and completed exactly once
to 007.
