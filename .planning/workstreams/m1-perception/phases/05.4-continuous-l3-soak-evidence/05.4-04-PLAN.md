<context>
Exact `[start,end)` database evidence is authoritative. Current `/health` and Fly logs are diagnostic only. `l3-soak-checkpoint` accepts shorter intervals; `l3-soak-verify` requires exactly 24 hours. Both fail closed for missing/unavailable data. Canonical identities are `soak_hash = sha256(start,boot identity,release,image_ref,machine_version,mapping_hash,acceptance_config_hash)`, `interval_hash = sha256(soak_hash,end)`, and `report_hash = sha256(canonical report payload without report_hash)`.

Stable interfaces:

- `VerdictStatus(StrEnum)` = `PASS|NOT-CLOSED` and frozen `VerdictReason(code: str, message: str)`.
- `SoakManifest` is canonical JSON containing schema version, T0/T24, five exact report bounds/paths, boot/release/machine/version/image ref+digest, mapping hash, `acceptance_config_hash`, immutable `allowed_event_kind_exceptions` (default empty), and `soak_hash`; `.manifest_hash` excludes itself.
- `L3SoakReport` canonical JSON includes manifest/soak/interval/report hashes, raw-row-set hash (all five table rows including server `recorded_at` plus exact SQL coverage aggregates), UTC bounds, identity/config anchors, row/tick/gap/cardinality/freshness/event/coverage results, status, and ordered reasons.
- `build_soak_report(evidence: EvidenceWindow, manifest: SoakManifest, start: datetime, end: datetime, require_24h: bool) -> L3SoakReport`.
- `render_report(report: L3SoakReport) -> str` is deterministic Markdown; CLI writes only stdout/stderr and never mutates evidence.
</context>
