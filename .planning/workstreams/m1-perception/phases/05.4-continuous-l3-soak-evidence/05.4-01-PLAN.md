<context>
Production head is 006. Generic migration detection does not recognize Python revisions, so the local 007 replay in Task 1 is a hard gate, while production migration remains exclusively in autonomous:false Plan 05.

Stable interfaces introduced here:

- `PromoteStatus(StrEnum)` = `success|frozen|underfilled|failed`.
- `RuntimeEventKind(StrEnum)` = `watchdog_stale|reconnect_reserved|reconnect_deferred|reconnect_started|reconnect_succeeded|reconnect_failed|ws_generation_changed|subscription_control_failed|subscription_compensated|evidence_writer_failed|evidence_writer_recovered|shutdown_signal|soak_manifest_bound|checkpoint_report_bound`.
- `AcceptanceConfig` canonically includes recipe bytes hash, sampler `30`, max sample gap `75`, promoter `300`, max start gap `360`, book/OHLC freshness `120`, expected markets/tokens `5/10`, retention days (minimum `30`), schema revision `007`, and code version; `.digest() -> str` is persisted as `acceptance_config_hash` in boots, promoter rows, samples, manifest events, and reports.
- frozen dataclasses `MarketPair`, `RuntimeIdentity`, `RuntimeBootRecord`, `PromoteRunRecord`, `HealthSampleRecord`, `MarketSampleRecord`, `SampleBatch`, `RuntimeEventRecord`, `EvidenceStatus`, `EvidenceWindow`, and `RetentionBounds` in `l3_evidence.py`.
- `stable_sha256(value: Mapping[str, object] | Sequence[object]) -> str` uses UTF-8 canonical JSON with sorted keys and compact separators.
- `L3EvidenceRuntime(identity: RuntimeIdentity, boot_id: UUID | None = None, started_at: datetime | None = None)` owns monotonic run/sample/event sequences, pending runtime events (bounded to 128), desired/committed/evidenced membership, per-token evidence, and persisted-success anchors.
- `L3EvidenceStore(dsn: str)` exposes async `append_boot`, `append_promote_run`, `append_sample`, `append_event`, `fetch_status`, `fetch_window`, and `retention_bounds`; it has no UPDATE/DELETE/boot-finalization API. Append methods return `bool`, never expose the DSN, and never update runtime anchors themselves.
- `L3RetentionOperator(dsn: str)` is a separate operator-only client exposing only `run_retention_cleanup(*, cutoff, protected_start, protected_end) -> RetentionCleanupResult`; it invokes `l3_retention_cleanup` and never issues raw DELETE. It accepts only the dedicated retention credential, never the daemon DSN.
</context>
