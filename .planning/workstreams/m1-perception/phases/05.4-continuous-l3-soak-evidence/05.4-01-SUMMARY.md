## Decisions Made

- Kept append-record field names and millisecond units identical to database
  columns so the store has no hidden rename/unit conversion layer.
- Defined `WsMembershipSnapshot` in the evidence module; Plan 02 imports it into
  `WsConsumer`, preserving the acyclic `ws_consumer → l3_evidence` direction.
- Added `l3_evidence_daemon` as a NOLOGIN capability instead of treating the
  PostgreSQL owner or Supabase `service_role` as the future daemon LOGIN.
- Required exclusive role membership in both store and retention clients so a
  mixed or superuser credential fails closed under provisioning mistakes.
- Used PostgreSQL-style JSON text sizing for event detail and prohibited floats/
  NUL at this boundary; compact canonical JSON remains the hash representation.

## Deviations from Plan

### Auto-fixed Issues

**1. Server timestamp and role-collision hardening**
- **Found during:** Task 1 independent review
- **Issue:** Client `recorded_at` could expand the future bound; an existing
  retention role could be silently trusted and later dropped.
- **Fix:** Server overwrites timestamps; capability creation now fails closed on
  collisions; complete five-table retention branches are exercised.
- **Committed in:** `86b5f60`

**2. Runtime event constraint mismatch**
- **Found during:** Controller cross-plan contract review
- **Issue:** Migration used obsolete event names while the approved runtime
  contract locked 14 different event kinds.
- **Fix:** Database constraint and live catalog test now require exactly the 14
  approved values.
- **Committed in:** `40ffd26`

**3. Task 2 constructor contract was underspecified**
- **Found during:** Task 2 pre-code ambiguity gate
- **Issue:** Plans named dataclasses but did not lock fields, units, or shared DTO
  ownership, risking incompatible store/promoter/sampler implementations.
- **Fix:** Established a direct-column typed contract, acyclic DTO ownership,
  strict runtime types, and durable-anchor semantics before implementation.
- **Committed in:** `3bc1ed9`, `136738b`

**4. Store generic SQL and post-commit close semantics**
- **Found during:** Task 3 and whole-branch reviews
- **Issue:** A private helper accepted arbitrary SQL, and connection close failure
  could turn an already committed append into `False`.
- **Fix:** Fixed operation-to-SQL mapping closes the surface; acknowledged commit
  truth survives bounded cleanup failures.
- **Committed in:** `96a2ab6`, `7d2560d`

**5. Production credential topology and cross-layer validation**
- **Found during:** Whole-branch review
- **Issue:** The existing owner DSN could bypass append-only controls; DB hashes,
  record enums/UUID/bools/detail root, and JSON size had cross-layer gaps.
- **Fix:** Added future masked runtime DSN, exclusive daemon capability/preflight,
  lowercase hash regexes, exact catalog checks, strict constructors, and matching
  JSONB boundary behavior.
- **Committed in:** `7d2560d`, `03a456f`
