# Phase 05.4 Learnings: Continuous L3 Soak Evidence

## Decisions

### Make PostgreSQL the evidence-time authority

All five evidence tables use server-owned `recorded_at`, append-only triggers,
bounded occurrence windows, and one isolated retention RPC. Runtime append
inputs cannot select the evidence timestamp or later rewrite a row.

**Rationale:** A 24-hour verdict must not be healable by client clock choice,
backfill, UPDATE, or ordinary DELETE.
**Source:** `05.4-01-SUMMARY.md`

---

### Model membership as desired, committed, and evidenced

Reconnect intent, successful current-generation control, and successful
current-generation depth persistence are separate immutable sets. A send,
proposal, or old-generation book cannot satisfy evidence cardinality.

**Rationale:** One `active_set` collapsed three different truths and allowed
false 10/10 claims.
**Source:** `05.4-02-SUMMARY.md`

---

### Preserve schedule identity and observation time as separate clocks

`scheduled_at` identifies the exact boot grid; `sampled_at` records when the
aggregate observation actually completed. Missing slots are visible, while
gaps and freshness use real observation times.

**Rationale:** Backfilling or pretending a late observation happened on the
boundary would make cadence evidence unverifiable.
**Source:** `05.4-03-SUMMARY.md`, `05.4-04-SUMMARY.md`

---

### Bind the verdict before T0

One immutable manifest fixes boot/release/image, mapping, AcceptanceConfig,
T0/T24, allowed event-kind exceptions, and the five cumulative report paths.
The database records one matching pre-T0 binding.

**Rationale:** The identity, thresholds, exceptions, and artifact locations
must be commitments, not explanations selected after observing the run.
**Source:** `05.4-04-SUMMARY.md`

---

### Separate production capabilities and authorizations

Migration owner, daemon runtime, and retention cleanup use disjoint
credentials. Migration, runtime provisioning, retention provisioning, and
deployment each had their own target/identity gate.

**Rationale:** A compromised runtime must neither migrate schema nor erase
failure history, and one approval must not implicitly authorize another
production mutation.
**Source:** `05.4-04-SUMMARY.md`, `05.4-05-SUMMARY.md`

---

### Compensate control ambiguity, not business-evidence absence

Send failure, generation drift, and cancellation still close the ambiguous
generation. A successful final same-generation subscribe followed by missing
depth evidence retains the socket and retries only missing identities.

**Rationale:** Closing a healthy socket on an evidence timeout amplified one
intermittent missing book into a self-sustaining reconnect loop.
**Source:** `05.4-05-SUMMARY.md`

---

## Lessons

### Task-level GREEN does not prove the cross-task chain

Whole-branch reviews found cadence, terminal-write, automatic-deploy,
generation, writer-causality, and shutdown false greens after focused tests
had passed. Each required a deterministic regression at the actual link.

**Context:** Evidence correctness crosses writers, shared runtime state,
public health, schema constraints, and the final verifier.
**Source:** `05.4-02-SUMMARY.md`, `05.4-03-SUMMARY.md`,
`05.4-04-SUMMARY.md`

---

### RFC WebSocket Ping is not Polymarket's text heartbeat

`websockets.connect(ping_interval=10)` did not satisfy the venue's text
`PING`/`PONG` contract. A5 recorded only 7/2/7 current-generation evidenced
tokens during repeated connection churn.

**Context:** Protocol-layer liveness and application-layer venue liveness can
share names while being independent requirements.
**Source:** `05.4-05-SUMMARY.md`

---

### Sibling task creation is not startup ordering

Release 68 let promoter run 0 start before the WebSocket published generation
1. A one-time wait on the real active-connection truth fixed the pre-attempt
boundary without relaxing later generation-change failures.

**Context:** Event-loop scheduling order cannot be inferred from task creation
order.
**Source:** `05.4-05-SUMMARY.md`

---

### A reconnect is not a universally safe recovery primitive

A6 showed that destructive compensation for missing depth evidence can
continually reset the generation before evidence converges. Recovery logic
must classify what is uncertain before choosing a reset.

**Context:** The socket control result was known; only one or more business
books were absent.
**Source:** `05.4-05-SUMMARY.md`

---

### Availability failure and verdict failure need different artifacts

T+12 and the first T+24 read timed out before an O_EXCL report existed.
Re-running the exact read was safe. A persisted canonical NOT-CLOSED report
would instead have been permanent.

**Context:** Fail-closed means “no false PASS,” not “every transient read
failure must fabricate a terminal business verdict.”
**Source:** `05.4-05-SUMMARY.md`

---

### Monitoring scope is part of evidence semantics

A live monitor without `< T24` saw a post-window mapping change and falsely
rejected A7. Exact `[T0,T24)` SQL retained one mapping; the first different
promoter mapping occurred at T24+30 seconds.

**Context:** A broader current-state query cannot judge an immutable historical
interval.
**Source:** `05.4-05-SUMMARY.md`

---

### Acknowledged database truth survives cleanup trouble

An append that committed before connection-close failure remains successful;
otherwise cleanup behavior could convert durable truth into a false failed
write and trigger duplicate recovery.

**Context:** Transaction outcome and client resource cleanup are distinct
facts.
**Source:** `05.4-01-SUMMARY.md`

---

## Patterns

### Identity-chain qualification

Trace one approved source SHA through workflow, Fly release/image/machine,
database boot, pre-T0 manifest, five reports, and final raw-row re-query.

**When to use:** Any production claim whose meaning depends on exact deployed
code and one runtime incarnation.
**Source:** `05.4-05-SUMMARY.md`

---

### Immutable rejected-attempt ledger

Keep every rejected boot, manifest, binding, and created report unchanged.
After a repair, begin with a new exact deployment identity and clock.

**When to use:** Long-running qualification where retrospective repair would
otherwise erase the evidence that exposed the defect.
**Source:** `05.4-05-SUMMARY.md`

---

### Atomic sample truth

Read one immutable runtime snapshot and one aggregate database state, then
commit one health row plus exactly five distinct market children as a unit.

**When to use:** A process-level verdict is valid only if every member-level
observation came from the same logical cut.
**Source:** `05.4-03-SUMMARY.md`

---

### Chain-truth health checks

For each check, name the real mutation, authoritative runtime field, public
reader, ungated configuration path, and end-to-end fault injection.

**When to use:** A fail-soft writer or asynchronous pipeline must remain
observable through the operator-facing health surface.
**Source:** `05.4-03-SUMMARY.md`

---

### Producer-before-writer shutdown

Stop and reap all event producers before allowing the ordered event writer to
drain and exit, with every cleanup phase sharing one deadline.

**When to use:** Cancellation cleanup can emit final durable events and an
early consumer exit would lose them.
**Source:** `05.4-03-SUMMARY.md`

---

### Exact-interval monitor parity

Copy the verifier's timestamp column, lower/upper bounds, and inclusivity into
any monitor that can accept or reject an immutable run.

**When to use:** Live tables continue receiving rows after a sealed reporting
window.
**Source:** `05.4-05-SUMMARY.md`

## Surprises

### Production truth required seven attempts

The plan expected one rollout and one eligible soak, but A1–A6 and release 68
exposed separate mapping, coverage, freshness, heartbeat, startup, and
quiet-refresh problems before A7 passed.

**Impact:** Production qualification became an iterative fault-discovery loop;
the strict contract was preserved instead of softened.
**Source:** `05.4-05-SUMMARY.md`

---

### A standard heartbeat setting still violated the venue contract

The client looked heartbeat-enabled while omitting the exact application text
message required by Polymarket.

**Impact:** Connection churn appeared as incomplete membership evidence rather
than an obvious configuration error.
**Source:** `05.4-05-SUMMARY.md`

---

### One-second startup ordering permanently rejected a boot

Promoter run 0 raced generation initialization and correctly wrote a terminal
failure before readiness.

**Impact:** Restarting the same release could not make the failed boot eligible;
a structural gate and new release/boot were required.
**Source:** `05.4-05-SUMMARY.md`

---

### Recovery logic created the outage it was trying to repair

Whole-generation compensation for missing business evidence repeatedly reset
the socket before the next generation could converge.

**Impact:** A single intermittent book absence became persistent 10/10/8
evidence failure and invalidated A6.
**Source:** `05.4-05-SUMMARY.md`

---

### The final apparent mapping failure was outside the window

The second mapping first appeared 30 seconds after T24, but a convenience
query without the upper bound made it look like an in-window identity change.

**Impact:** Boundary SQL prevented an operator-monitor bug from discarding a
valid 24-hour evidence chain.
**Source:** `05.4-05-SUMMARY.md`
