## Decisions Made

- Kept the sampler observation-oriented: a 76-second pause creates one later
  sample with a real gap, not two invented rows.
- Required `evidenced_at` to exist, be non-future, and be strictly younger than
  the book threshold for each Yes/No token. The durable book timestamp must be
  at least that same frame timestamp, preventing an old generation's DB row from
  being combined with current-generation membership.
- Used one failure latch per writer channel. Global writer health remains false
  while any failed channel remains unresolved, even if another writer succeeds;
  per-channel completion clocks prevent cross-task completion order from
  rolling time backward after a database ACK.
- Event queue ownership is peek/ACK. A transient failure retains the exact head;
  a permanent event identity/payload conflict quarantines only that head, records
  sticky integrity truth, and permits the tail to persist.
- Normal signal shutdown first cancels and reaps every producer, then sets
  `producers_done`, then lets the writer drain to empty. Cancellation during
  either graceful wait or final force-reap still reaps owned tasks inside the
  original deadline before propagating.

## Deviations from Plan

### Auto-fixed Issues

**1. Minimal mapping privilege for the runtime sampler**
- **Found during:** Task 1
- **Issue:** The dedicated evidence daemon could append evidence but could not
  read the five canonical market mappings required for one aggregate sample.
- **Fix:** Granted only SELECT on `markets_latest`, with matching downgrade
  revoke and live privilege tests; no write/owner capability was added.
- **Committed in:** `ac35e3d`

**2. Durable runtime-event replay and poison-head isolation**
- **Found during:** Task 2 independent reviews
- **Issue:** A lost ACK could duplicate or misidentify an event, while one
  permanent conflict could block all later transitions.
- **Fix:** Added idempotent insert plus exact readback equality, explicit
  integrity conflict, poison-head quarantine, sticky integrity truth, bounded
  detail values, and continued ordered tail persistence.
- **Committed in:** `138ebff`, `81f28b8`

**3. Current-generation health conjunction**
- **Found during:** Task 3 and whole-branch review
- **Issue:** Fresh DB timestamps could bless stale membership from another WS
  generation, and a current runtime could bless a prior-generation sample.
- **Fix:** Required current generation on persisted health inputs, fresh
  per-token `evidenced_at`, and a durable book timestamp from the same-or-later
  frame before a market sample can pass.
- **Committed in:** `8189dee`, `22defa6`

**4. Causal writer recovery**
- **Found during:** Whole-branch review
- **Issue:** Sample, promoter, boot, and event writers shared one boolean/time;
  unrelated success forged recovery and cross-channel completion order could
  throw after a durable database commit.
- **Fix:** Added independent channel latches and completion clocks, aggregate
  fail-closed status, and recovery only after every failed channel recovers.
- **Committed in:** `22defa6`

**5. Supervised lossless shutdown**
- **Found during:** Task 4 and whole-branch cancellation probes
- **Issue:** Early task exits could be ignored; event writer could exit before a
  producer's cancellation cleanup emitted its final event; cancellation during
  final reap could return while owned tasks survived.
- **Fix:** Added task supervision, same-tick signal priority, producer-done
  ordering, bounded listener close, two-stage reap, deadline fail-closed, and
  cancellation-safe cleanup around both reap phases.
- **Committed in:** `5ee7f0b`, `bbf0fe0`, `61b9a86`, `22defa6`, `9167d77`
