## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions → Fly.io API | secret-bearing flyctl call with FLY_API_TOKEN (organization-scope) |
| scripts/fly_secrets_sync.sh → flyctl → Fly secret store | local .env contains real secrets; bash glob/iteration must not leak via set -x |
| paths-filter omission | a future commit modifying L2-relevant files but not in filter list = silent skip → drift |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Information Disclosure | fly_secrets_sync.sh `set -x` debug leak prints secrets to terminal/log | mitigate | Script header: `set -euo pipefail` (no `-x`); explicit `echo "syncing KEY (value redacted)"` instead of `echo $KEY=$VALUE`. Wave 0 test asserts script does NOT contain `set -x` or `set -ex`. |
| T-03-02-02 | Tampering | malicious commit changes paths-filter to skip L2 deploys silently | mitigate | Wave 0 test asserts paths list includes minimum file set (`l2_main.py`, `ws_market_client.py`, `fly-l2.toml`). Reviewer-only via PR (mainline pushes by user only). |
| T-03-02-03 | Spoofing | rogue PR sets `FLY_API_TOKEN` to attacker token | accept | GH secret scope is repo-owner-controlled; PR from fork CANNOT read secrets (GHA security default). Acceptable. |
| T-03-02-04 | Denial of Service | first deploy floods Fly proxy → cooling-off | accept | flyctl deploy is rolling by default; `--wait-timeout 600` bounded; concurrency group prevents parallel deploys |
| T-03-02-05 | Repudiation | no record of what secrets were synced when | mitigate | Script writes timestamp + KEY names (NOT values) to stdout; GHA log retention is 90d; user runs locally + can pipe to `tee scripts/.secrets-sync-log` (gitignored) |
| T-03-02-06 | Elevation of Privilege | flyctl secrets pushed to wrong app (e.g., L2 secret pushed to L1 by mistake) | mitigate | Script iterates app names explicitly (`for APP in polyarb-l1 polyarb-l2; do ... done`) — both apps get identical secrets per Phase 02.1 D-22 (shared SCAN_SHARED_SECRET). No accidental cross-pollination possible. |

    # fly_secrets_sync.sh — Push .env to BOTH polyarb-l1 + polyarb-l2 idempotently.
    # Phase 02.1 D-22 invariant: same SCAN_SHARED_SECRET on both apps.
    # T-03-02-01: NEVER use `set -x` (leaks secret values).
    set -euo pipefail

    ENV_FILE="${ENV_FILE:-.env}"
    APPS=("polyarb-l1" "polyarb-l2")
    DRY_RUN="${DRY_RUN:-0}"

    if [ ! -f "${ENV_FILE}" ]; then
      echo "ERROR: ${ENV_FILE} not found" >&2
      exit 1
    fi

    # Filter out comments + blank lines from .env (per 03-PATTERNS.md File 5 Gotcha)
    # NEVER cat the file as-is — `# secret backup`-style comments would fail flyctl parse.
    SECRETS_RAW="$(grep -v '^#' "${ENV_FILE}" | grep -v '^$' | grep '=' || true)"

    if [ -z "${SECRETS_RAW}" ]; then
      echo "ERROR: no secrets found in ${ENV_FILE} after comment/blank filter" >&2
      exit 1
    fi

    # Build args without echoing values
    SECRET_KEYS="$(echo "${SECRETS_RAW}" | awk -F= '{print $1}')"
    SECRET_COUNT="$(echo "${SECRET_KEYS}" | wc -l | tr -d ' ')"

    echo "=== Syncing ${SECRET_COUNT} secrets to ${#APPS[@]} apps ==="
    echo "Apps: ${APPS[*]}"
    echo "Keys (values redacted):"
    echo "${SECRET_KEYS}" | sed 's/^/  - /'
    echo ""

    if [ "${DRY_RUN}" = "1" ]; then
      echo "DRY_RUN=1 — skipping actual flyctl secrets set"
      exit 0
    fi

    for APP in "${APPS[@]}"; do
      echo "=== Syncing → ${APP} ==="
      # Pipe secret lines as args. --stage = no machine restart (atomic apply at end).
      # shellcheck disable=SC2046
      flyctl secrets set -a "${APP}" --stage $(echo "${SECRETS_RAW}" | tr '\n' ' ')
      echo "Staged. Applying…"
      flyctl secrets deploy -a "${APP}"
      echo "${APP}: ${SECRET_COUNT} secrets applied."
      echo ""
    done

    echo "=== Done — all ${SECRET_COUNT} secrets synced to all ${#APPS[@]} apps ==="
