<objective>
Build the WS dynamic-subscribe API on top of `WsConsumer`, and fix the Pitfall-5 race condition where `l2_candidate_refresh.on_snapshot_complete` (line 417) clobbers L3 tokens via full-list overwrite of `_subscribed_assets`.

Two concerns in one plan because they touch the same module (`ws_consumer.py`) and `l2_candidate_refresh.py:417` — refactoring `_subscribed_assets` into `_candidate_set` + `_l3_active_set` is the cleanest way to land both at once without bifurcating ownership.

Purpose: Without this, the L3 promoter (Plan 04) has no way to push subscriptions mid-connection — would have to wait for the next watchdog timeout to reconnect, defeating the entire L3 design. And without the race fix, every 60s NOTIFY would silently delete L3 tokens.

Output: New methods + refactor + 2 new test files. GAP-401 liveness gate is NOT touched — it sits on the same `_current_ws` field that this plan uses for send-after-connect.
