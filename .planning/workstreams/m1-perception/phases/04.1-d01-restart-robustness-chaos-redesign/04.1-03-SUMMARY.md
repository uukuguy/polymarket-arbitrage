# Phase 04.1 Plan 03: G-03 In-Band WS-Kill Chaos Endpoint Summary

**One-liner:** HMAC-gated POST /control/chaos/ws-test-kill flips a process-local flag on a running L2 process so chaos runs against the live 60-asset machine without a restart.

## What Was Built

### The Problem (G-03)
Phase 04 chaos triggered WS kill via `flyctl secrets set POLYARB_WS_TEST_KILL=1`, which **restarts** the Fly machine. The pre-storm 60-asset process was killed before the storm began — making Pitfall 4 (watchdog false-trip on a healthy long-lived process) completely unobservable (04-SOAK-LOG §G-03).

### The Fix
Three interlocking changes:

**1. ws_consumer.py — process-local flag**
- Added module-level `_ws_test_kill_flag: bool` seeded from env at import (cold-start backward compat)
- Added `set_ws_test_kill(enabled: bool)` and `get_ws_test_kill() -> bool` public API
- Changed `_check_ws_test_kill()` to read `_ws_test_kill_flag` (NOT `os.getenv`) — enables in-flight toggle without restart

**2. l2_control.py — HMAC chaos handler (new file)**
- `POST /control/chaos/ws-test-kill` — parses `{"enabled": bool}`, calls `set_ws_test_kill`, returns `{"status":"ok","ws_test_kill":bool}`
- Handler does NOT re-verify HMAC — middleware gate is delegated to ControlAuthMiddleware

**3. l2_app.py — ControlAuthMiddleware wiring**
- L2's first HMAC admin endpoint: `Middleware(ControlAuthMiddleware, secret=...)` added to Starlette app
- Route registered under `/control/` so path-guard covers it; `/health` + `/healthz` bypass automatically

**4. l2_health.py — chain-truth update**
- `chaos:ws_test_kill_flag` sub-check now reads `get_ws_test_kill()` (process-local) instead of `os.getenv`
- In-flight toggle immediately visible in `/health` without needing a restart

**5. Makefile**
- `chaos-ws-kill ON=1|0`: HMAC-signed curl using openssl from dev host; sources `.env` for secret
- `chaos-l2-inj4-throughput`: storm/cleanup steps rewired from `flyctl secrets set/unset` to `$(MAKE) chaos-ws-kill ON=1/0`

Chain complete: endpoint → `_ws_test_kill_flag` ← `_check_ws_test_kill` and `/health`. No dead-code gate.

## HMAC Path-Guard Verification

Route `/control/chaos/ws-test-kill` is registered UNDER `/control/` — `ControlAuthMiddleware` path-guard (`/control` prefix) covers it. `/health` and `/healthz` are not under `/control/` so they bypass the guard automatically (T-04.1-08 mitigated).
