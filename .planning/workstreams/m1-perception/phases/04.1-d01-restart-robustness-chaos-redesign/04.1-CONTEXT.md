<decisions>
## Implementation Decisions

### G-02 — D-01 fetch 跨 restart 健壮性
- **D-01.1:** 用 **eager startup-prime** 修法（不用 scheduled timer / boot-align）。catchup 完成后（无论 missed 数量），无条件 dispatch 一次 synthetic prime payload，强制跑一次 markets_latest fetch。
- **D-01.2:** 挂载点 = `src/polyarb/daemon/l2_main.py:416-417` 的 `else: logger.info("event-bus catchup: no missed snapshots")` 分支 — 这里以及 missed>0 分支结束后都要保证至少 prime 一次。具体实现 planner 定（最简：catchup try 块结束后无条件调一次 `_dispatch_on_snapshot({"snapshot_id": -1, "_startup_prime": True, "ts_s": <now>})`）。
- **D-01.3:** prime 调用安全性依赖 G-01 fix（`_last_refresh_at_s = -REFRESH_DEBOUNCE_S - 1.0` 已 ship at commit 39c60ef）— first call 必过 debounce，prime 不会被吞。
- **D-01.4:** prime payload 的 `snapshot_id` 用 sentinel（如 -1）或 None — `on_snapshot_complete` 现有逻辑要能容忍它（不去查真实 snapshot row）。planner 确认 on_snapshot_complete 对 sentinel snapshot_id 的处理（它只用 markets_latest fetch，不直接读 snapshot 表 — 见 04-02 实现）。
- **D-01.5:** fail-soft 保持 — prime fetch 失败走现有 `_last_known_markets_rows` fallback + chain-truth surface，不 crash daemon。

### G-03 — chaos primitive 从 rolling-restart 重设计成 in-flight 注入
- **D-03.1:** 用 **in-band HTTP endpoint** 修法（不用 SIGUSR1 signal，不用 document-only）。
- **D-03.2:** 新增 `POST /admin/chaos/ws-test-kill` endpoint，HMAC-gated，复用 `src/polyarb/http/control.py` 的现有 HMAC 中间件 pattern（Phase 02.1 `ControlAuthMiddleware` + `control_auth_middleware`，keyed by `POLYARB_SCAN_SHARED_SECRET`，`hmac.compare_digest` 常量时间）。
- **D-03.3:** endpoint 翻一个**进程内 atomic flag**（module-level 或 app.state），`src/polyarb/daemon/ws_consumer.py:65` 的 `os.getenv("POLYARB_WS_TEST_KILL") == "1"` 改成读这个进程内 flag（env var 作为 cold-start 初值仍保留兼容，但运行时由 endpoint 翻转）。**不重启进程** — pre-storm 的 60-asset 进程在 storm 期间存活，真测 in-flight WS close + reconnect。
- **D-03.4:** endpoint 挂在 L2 app（`src/polyarb/http/l2_app.py` — 当前只有 /health + /healthz，需要加 admin route + HMAC 中间件）。L2 app 此前无 /control/*（Plan 03 注释说 control 是 L1-only）— 本 phase 给 L2 引入第一个 HMAC-gated admin endpoint。
- **D-03.5:** endpoint body 设计 planner 定（最简 `{"enabled": true/false}` 翻 flag on/off，让 chaos 能 set 也能 clear，不依赖 unset env）。
- **D-03.6:** 安全 — endpoint 必须 HMAC-gated 不可外部利用（T-04.1-XX）；flag 是 chaos-only，prod 正常路径默认 false。fly-l2.toml MUST NOT 含 POLYARB_WS_TEST_KILL（保持 ws_consumer.py:42-43 现有 invariant）。

### G-04 — RSS 测对 Python L2 进程
- **D-04.1:** 用 **/health `process:rss_kb` 子检查** 修法（首选；可叠加 Makefile 改读 /health）。
- **D-04.2:** `/health` 加子检查 `process:rss_kb`，值 = `psutil.Process().memory_info().rss / 1024`（当前进程 = Python L2 daemon，不是 PID 1 hallpass）。psutil 已是 dev dep（Phase 03.1 L11）— 确认它在 prod runtime deps 里（chaos 要 prod /health 暴露 RSS，psutil 必须在 runtime 不只 dev）。
- **D-04.3:** Makefile `chaos-l2-inj4-throughput` 的三处 RSS 读（lines 945/953/963）从 `flyctl ssh console -C 'grep VmRSS /proc/1/status'` 改成 `curl /health | jq '.checks["process:rss_kb"][0].observedValue'` — chaos 和 operator 走同一 source，不再依赖 flyctl ssh。
- **D-04.4:** `process:rss_kb` 子检查 status 设计 planner 定（最简纯 informational status=pass，或加一个 soft 阈值 warn）— 它主要是 observability，不该轻易 fail /health。

### D-06 verdict re-run（本 phase 内闭环）
- **D-06.1:** Phase 04.1 scope **含** prod chaos re-run。三个 fix ship + deploy 后，re-run `make chaos-l2-inj4-throughput` 拿真 D-06 verdict。
- **D-06.2:** 这是 human-verify checkpoint（同 04-04 Task 3）— D-06 三指标 pass/fail 需人看真实 prod 测量。
- **D-06.3:** 补 **Pitfall 4 watchdog false-trip 观察** — G-03 fix 后 storm 不再重启进程，60-asset 进程在 storm 边界存活，终于能观察 watchdog 在 healthy window 是否 false-trip（上次被 G-03 阻塞未观察到）。
- **D-06.4:** verdict 记录进 `04.1-SOAK-LOG.md`（新建，或 extend 04-SOAK-LOG 风格）。若仍撞低活跃日历窗口导致 candidate set 退化（A2），documented-deferral 不算失败，但记录 actual N。

### the agent's Discretion
- prime payload 的精确字段结构（sentinel snapshot_id 值、是否带 `_startup_prime` 标记）
- admin chaos endpoint 的 body schema + flag 存储位置（module-level vs app.state）
- `process:rss_kb` 子检查的 status 逻辑（纯 informational vs soft 阈值）
- plan 拆分（3 fix 是 1 plan 还是 3 plan + 1 re-run plan）— planner 按依赖定 wave
