# Phase 04.1 Plan 02: process:rss_kb /health sub-check + psutil runtime promotion Summary

**PID-1-hallpass bug fixed (G-04): /health now exposes current Python L2 daemon RSS via psutil.Process(), psutil promoted to runtime dep, and chaos Makefile reads RSS from /health JSON instead of flyctl ssh procfs**

## Accomplishments

- Added `process:rss_kb` informational sub-check to `/health` using `psutil.Process().memory_info().rss / 1024`. The fix targets the PID-1-hallpass bug from Phase 04 SOAK-LOG §G-04: `flyctl ssh grep VmRSS /proc/1/status` reads PID 1 (the Fly init/shim), not the Python L2 daemon. `psutil.Process()` with no arg = `os.getpid()` = the live daemon.
- Promoted `psutil` from `[project.optional-dependencies].dev` to `[project.dependencies]` so prod `/health` can import it without dev extras.
- Replaced all 3 `flyctl ssh console -C 'grep VmRSS /proc/1/status'` lines in `chaos-l2-inj4-throughput` Makefile recipe with `jq '.checks["process:rss_kb"][0].observedValue'` reads on already-captured `/tmp/inj4t-t{1,2,3}.json` snapshots. Chaos and operator now read RSS from one source.

## Decisions Made

- **D-04.4 honored strictly**: No `_severity(overall, rss_status)` call even on fail-soft `warn` path. The comment "intentionally NO `overall = _severity(overall, rss_status)`" is explicit in the code.
- **Lazy-import inside try/except**: mirrors the `get_last_fetch_success_at_s` precedent (l2_health.py:316). A missing psutil dep produces a `warn` row in /health, not an import-time crash.
