<objective>
Fix G-03 (chaos primitive redesign: rolling-restart → in-flight injection). Phase 04
chaos triggered the WS kill via `flyctl secrets set POLYARB_WS_TEST_KILL=1`, which
RESTARTS the machine — so the pre-storm 60-asset process never survived into the
storm, and Pitfall 4 (watchdog false-trip on a healthy long-lived process) was
never observable (04-SOAK-LOG §G-03). Fix per D-03.1/D-03.2/D-03.3:

1. Add an HMAC-gated `POST /control/chaos/ws-test-kill` endpoint (reuses the
   existing `ControlAuthMiddleware` from `polyarb.http.control` unchanged — its
   path-guard is hard-coded to `/control`, so registering UNDER `/control/...` is
   the zero-new-middleware path per D-03.2 preference).
2. The endpoint flips a PROCESS-LOCAL atomic flag (body `{"enabled": true/false}`)
   — set AND clear, no restart, no unset env.
3. `ws_consumer._check_ws_test_kill` reads the process-local flag at runtime; the
   env var seeds the flag only at cold-start (backward compat).
4. `/health chaos:ws_test_kill_flag` reflects the process-local flag.
5. `make chaos-ws-kill` helper curls the endpoint with a computed HMAC signature.

Purpose: chaos kills the WS on a RUNNING process so the 04.1-04 re-run measures
true in-flight close + reconnect AND observes the watchdog across a healthy window.

Output: new `l2_control.py` handler + middleware wiring + process-local flag +
/health surface update + `make chaos-ws-kill` + unit tests + threat model.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external → /control/chaos/ws-test-kill | Untrusted internet → prod L2 HMAC-gated chaos endpoint (first admin endpoint on L2) |
| endpoint handler → ws_consumer process-local flag | In-process mutation of the WS-kill flag (no persistence, no restart) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04.1-01 | Spoofing | /control/chaos/ws-test-kill | mitigate | Reuse ControlAuthMiddleware: X-Signature = HMAC-SHA256(body, POLYARB_SCAN_SHARED_SECRET), `hmac.compare_digest` constant-time; missing/invalid sig → 401. Endpoint UNREACHABLE without the shared secret. |
| T-04.1-02 | Tampering | request body `{"enabled":bool}` | mitigate | HMAC is computed over the exact body bytes; any body tamper invalidates the signature (middleware re-injects the verified body to the handler). |
| T-04.1-03 | Repudiation | flag flip | accept | Handler logs the flip (enabled=true/false) via loguru → Axiom; HMAC-gated channel means the actor holds the shared secret (operator). Low value, accepted. |
| T-04.1-04 | Info disclosure | endpoint response | mitigate | Response body returns only `{"status":"ok","ws_test_kill":bool}` — no secret material, no config dump (T-03-03-06 whitelist discipline). |
| T-04.1-05 | DoS (leave WS killed) | process-local flag persisting after chaos | mitigate | Body supports `{"enabled":false}` to CLEAR the flag in-band (no unset-env dependency); flag defaults False; `make chaos-ws-kill ON=0` + the recipe cleanup step always clears. Flag is process-local → a natural restart also resets it to the (False) env seed. |
| T-04.1-06 | DoS (replay sets flag again) | replay of a captured signed request | accept | Idempotent set/clear (replaying `enabled:true` just re-sets True); operator clears with `enabled:false`. No nonce needed — same accepted-replay rationale as /control/unpause (T-02.1-8-04). HMAC-gated channel only. |
| T-04.1-07 | Elevation / prod-leak | POLYARB_WS_TEST_KILL accidentally set in prod config | mitigate | fly-l2.toml MUST NOT contain POLYARB_WS_TEST_KILL; CI-enforced by test_prod_fly_toml_never_sets_test_kill_flag (kept green). Env only SEEDS the cold-start flag (defaults False in prod). |
| T-04.1-08 | Tampering (path-guard bypass) | reaching the handler without the /control guard | mitigate | Route registered UNDER /control/* so ControlAuthMiddleware's hard-coded `/control` path-guard covers it; /health + /healthz remain the only unauthenticated routes. Unit test asserts 401 without signature. |

All HIGH-severity threats (T-04.1-01/02/04/05/07/08) are mitigated. No HIGH left as accept.
</threat_model>
