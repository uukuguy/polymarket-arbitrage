<objective>
Fix G-04 (RSS measured against the wrong process). Phase 04 chaos read
`grep VmRSS /proc/1/status` via `flyctl ssh`, but PID 1 in the Fly machine is not
the Python L2 daemon — it's the init/shim ("PID-1-hallpass bug", 04-SOAK-LOG §G-04),
so the RSS verdict for D-06 indicator 3 was meaningless. Fix per D-04.1:

1. Add a `/health process:rss_kb` informational sub-check using
   `psutil.Process().memory_info().rss / 1024` (the CURRENT process = the Python
   L2 daemon).
2. Promote `psutil` from dev-only to a runtime dependency (prod /health must
   import it).
3. Rewrite the three chaos Makefile RSS reads to `jq` the already-captured
   `/tmp/inj4t-t{1,2,3}.json` snapshots — chaos and operator now read RSS from
   the SAME source (/health), no flyctl ssh.

Purpose: D-06 indicator 3 (`rss_recovery <= rss_baseline * 1.30`) measures the
real daemon memory in the 04.1-04 re-run.

Output: new informational /health sub-check + runtime psutil + Makefile RSS reads
via /health + unit test.
</objective>

        "observedUnit": "kB",

        "output": rss_output,
        "time": _utc_now_iso(),
