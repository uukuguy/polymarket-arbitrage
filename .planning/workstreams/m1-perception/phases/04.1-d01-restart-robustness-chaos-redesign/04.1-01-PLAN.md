<objective>
Fix G-02 (D-01 fetch cross-restart robustness). Phase 04 prod chaos exposed that
when the L2 daemon restarts and catchup finds NO missed snapshots, the candidate
refresh never fires — `ws:subscribed_count` stays at the 3 bootstrap asset_ids
indefinitely (31 catchup-snapshot scenario in 04-SOAK-LOG §G-02). The fix is an
**eager startup-prime**: after the catchup try/except envelope closes,
unconditionally dispatch ONE synthetic prime payload through the existing
`_dispatch_on_snapshot` helper to force a `markets_latest` fetch.

Purpose: candidate set is populated on every cold start regardless of whether the
event-bus had missed snapshots, so the WS subscribes to the real candidate set
(not just 3 bootstrap ids) without waiting for the next live NOTIFY.

Output: one additive dispatch in `l2_main.py` + a unit test proving the prime
fires on both catchup paths (missed>0 and no-missed).
</objective>

```python
def _dispatch_on_snapshot(payload: dict) -> None:
    """Sync-callback bridge from asyncpg loop to async refresh handler."""
    event_listener.last_event_received_s = time.time()
    try:
        asyncio.create_task(
            on_snapshot_complete(payload, ws_consumer=ws_consumer,
                                 settings=settings, mirror=l2_mirror)
        )
    except Exception as e:  # noqa: BLE001
        logger.warning(f"on_snapshot_complete dispatch failed: {e!r}")
```
