<threat_model>
  <assets>
    - Paper-account balance, exact stake, realized PnL, and stop-loss authority.
    - Phase 4 durable account/position/operation rows and immutable close receipts.
  </assets>
  <trust_boundaries>
    - Float/string configuration and CLI values become trusted money only after centralized decimal quantization and range validation.
    - Legacy SQLite REAL and result JSON are untrusted migration inputs; integer micros/tagged JSON become authority only after validation.
  </trust_boundaries>
  <threats>
    - NaN/infinity/overflow could poison risk comparisons or SQLite writes: reject before mutation and roll back the transaction.
    - Partial/crashed migration could leave mixed authority: perform add/backfill/validation under BEGIN IMMEDIATE and make restart idempotent.
    - JSON bool is an int subclass and could forge micros: require exact int type, known tag, exact shape, and signed 64-bit range.
    - Compatibility dual-write could drift: calculate legacy REAL only from integer authority; never read it after migration.
    - Scope could leak into live order precision: add no wallet, signing, SDK, network, tick-size, or reconciliation behavior.
  </threats>
</threat_model>
