## 数据质量哲学（套利系统级，2026-04-28 SESSION 04 沉淀）

### 1. 完整性的本质：知道哪里不齐全 + 为什么

**反直觉但必须内化的**：完整性 ≠ 数据齐全。完整性 = **能解释每一处缺失**。

一般爬虫漏几条无伤大雅。套利系统漏一条 = 漏一次机会 = 漏钱。但简单追求"齐全"会演化成最危险的失败模式。

### 2. 阈值是反模式，规则是正模式

| 反模式（用阈值） | 正模式（用规则） |
|---|---|
| 缺 < 10 → 忽略 | 缺市场必须能识别为已知归类，否则 fail |
| 延迟 < 1s → 通过 | 延迟分布必须符合历史 P95，否则记录上下文调查 |
| 异常率 < 5% → OK | 每个异常必须能归类到已知根因，否则 fail |

**阈值让你在不理解时关上眼睛。规则强制理解。**

### 3. 告警麻木症（Alert Fatigue）

> IMDEA 论文里跑路的 bot 大多败给自己的告警麻木，不是市场。

机制：今天容忍 5 个，明天 10 个，后天 50 个，最后告警 = 不报。任何"调阈值"动作都该触发警觉——你是在用麻木换便利。

**纪律**：告警如果反复响，不是调阈值，**是查根因 + 升级归类系统**。

### 4. 套利从业者反射动作

> **任何缺失都假设它在告诉你什么。**

snapshot 漏了 5 个市场不是"算了"，是问"哪 5 个？为什么是这 5 个？是 zombie / resolving / negrisk group 故障 / API 抖动 / 还是真随机？"

每种根因对应不同的实战风险——zombie 风险低，negrisk group 故障风险极高（你正在套这个 group 等于盲眼下单）。

### 5. 操作化：根因归类系统

把"调查根因"机制化进系统的最小动作：

- `validation_issues` 表必须有 `category` 字段
- 已知类目示例：`zombie_market` / `resolving` / `api_jitter` / `api_unreachable` / `clob_missing` / `unknown`
- 新发现的根因模式立即手工补到归类，让 `unknown` 不断收敛
- 持续 unknown = 系统欠债

### 6. 一致性 > 完整性

**snapshot 必须代表同一时间点 T**。

- 部分失败补拉 = 拿 T+90s 数据冒充 T → 时间一致性破坏
- 比缺数据更危险：缺数据可标记可调查，时间漂移不可逆
- "重拉一次让它齐"是经典反模式

**优先级**：宁可 snapshot 标 `is_valid=false`（保留缺失信号），不要混入异时数据冒充齐全。

## 冷热存储分离的真正含义

**热/冷不是按"新/旧"分，是按"访问模式"分。**

| 访问模式 | 工具 | 例子 |
|---|---|---|
| 单点查询、低延迟 | SQLite (B-tree, 行式) | "市场 X 现在 best_ask 是多少？" |
| 跨时间扫描、列式聚合 | Parquet + DuckDB (列式压缩) | "过去 30 天 ETH 市场的流动性曲线" |

一份 1 小时前的 snapshot 如果没人再问"现在状态"了，它对系统就是冷数据，进 Parquet。SQLite 永远只服务"现在"。

**反模式**：所有 snapshot 都进 SQLite（按 timestamp 索引）— 表迅速膨胀到上亿行，列式聚合崩溃。
