# Phase 05.4 Plan 02 Task 3 — bounded cleanup review fix

## Review item

The promoter treated `_last_mirrored_market_ids` as the complete stale-badge
truth source. A legacy oversized cache therefore built an oversized
`current | prior` identity set and permanently failed with
`identity_limit_exceeded` before querying the database. It could neither
recover nor prove that all persisted stale badges were eventually cleared.

## TDD evidence

RED was observed for three new scenarios before production changes:

- bounded cleanup constant/query behavior did not exist;
- oversized legacy mirror state returned `identity_limit_exceeded` instead of
  converging from an empty stale DB page;
- a candidate-badge query failure was invisible and incorrectly terminalized
  as success.

GREEN now covers:

- 207 distinct stale identities converging over three ticks with a 100-row
  cap, with the first two ticks durably failed as `mirror_cleanup_pending` and
  the final tick successful;
- every query, current refresh, and stale-clear payload remaining at or below
  the explicit cap;
- the union of cleared IDs equaling the entire stale set, while the current
  five are refreshed every tick and never cleared;
- cache and diagnostic target sizes remaining bounded after every durable
  reconciliation tick;
- oversized legacy memory plus an empty stale DB page converging in one tick;
- query failure terminalizing as `mirror_failed` and succeeding on retry.

## Implementation

- Added `_MIRROR_RECONCILE_BATCH_SIZE = 100`.
- Every post-control tick refreshes the complete committed Yes target first.
- Stale recovery uses the verified postgrest-py 2.30 chain:
  `select("asset_id").not_.is_("l3_promoted_at_ts", "null")`
  `.not_.in_("asset_id", current).order("id").limit(100).execute()`.
- Only returned, non-current IDs are deduplicated and cleared.
- A full page conservatively yields `mirror_cleanup_pending`; a short page
  proves this bounded pass is complete.
- Query/update exceptions remain fail-soft but terminalize as retryable
  `mirror_failed` outcomes.
- `_last_mirrored_market_ids` is now a bounded diagnostic cache of only the
  durably recorded current target; the DB is the sole stale recovery source.
- Legacy oversized token-map/mirror caches are replaced only after a bounded
  reconciliation result and a successful terminal evidence append.
